## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
Version-skew rule (guiding decision 1): a long-running process may have the old `registry.py` loaded while a lazy import loads a newer `runtime.py`, or the reverse. So no live-imported module may hard-require a new registry symbol:
```python
# in runtime.py, engine.py, pipeline_warmup.py, routers/live.py (each self-contained)
try:
    from firm.strategies.registry import list_allocatable as _default_names
except ImportError:            # old registry already loaded in this process
    from firm.strategies.registry import list_strategies as _default_names
```
In `_build_categorized_strategies` (runtime.py:58):
```python
if config.get("strategies"): names = config["strategies"]     # explicit list: honoured as today
else:
    all_names = list_strategies(); names = _default_names()
    skipped = [n for n in all_names if n not in names]
    if skipped: log.warning("Default strategy list skips non-allocatable %s", skipped)
```
- Explicit lists in live configs are honoured exactly as today (both live configs list their strategies), so live behaviour is unchanged. Only configs that omit the list change, and that is logged at WARNING.
- `require_allocatable` is called only from new research and backtest entry points added by later tickets (P1-01 `backtest_logged`, P3-08). It is never placed inside the `try/except Exception` of `_build_categorized_strategies`. `allow_archived=True` is for legacy replays (`scripts/calibrate_danelfin_ai_score.py`, review-package reproductions).
- `analyst bucket` note for DEPRECATIONS.md: removing multi_factor, sentiment and event_driven would empty the fundamental and sentiment analyst buckets (`runtime.py:44-45`); that is one reason live removal is deferred.
DEPRECATIONS.md row template (one row per strategy): name, module path and line of the class, status now, target status, reason, evidence (file + number), live impact, reopen condition. `regime_hmm` row must say the risk `regime_overlay` (config/live.yaml ~L363) is a separate path and is not affected.

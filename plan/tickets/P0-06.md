## Rationale (cite source plan / literature)
The source plan never mentions that the code under change is being served live. Two firm-api services (IBKR :8000, Alpaca :8001) run with `Restart=always` from this checkout (`deploy/ai-trading.service`, `deploy/ai-trading-alpaca.service`: `WorkingDirectory=/local/store/git/ai-trading-system`, `ExecStart=.../.venv/bin/firm-api`). Memory entry "Never edit the live checkout" records the 9/28 incident: an uncommitted edit caused an ImportError in IBKR cycle 109. Importing `firm.api.app` runs `create_app()` at import (`app.py:176`), which loads every router and through them `firm.live.capital_gate` -> `firm.eval.robustness`/`firm.eval.metrics`; `firm.live.engine` imports `firm.runtime` (and so `firm.data.pit_store`) at module top. These modules are therefore EAGERLY loaded in both running services, and a merge touching them takes effect at the next process start (crash, `Restart=always`, reboot). Modules that request handlers import lazily (for example `firm.api.routers.live` -> `provider_utils` paths, `api/jobs.py` -> `experiments.runner`) can still load new code inside a running process, giving mixed old/new code (the 9/28 skew class). `firm.eval.*` is already in the live graph and is NOT on the forbidden list. This ticket makes every later ticket safe by (a) a worktree workflow, (b) a test that proves new code is not on the live import path, (c) a smoke script that proves live startup still builds, and (d) a resource policy for a 6-core / 11 GB host that is already busy.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
Isolation test:
```python
FORBIDDEN_PREFIXES = (
  "firm.validation", "firm.research", "firm.signals", "firm.costs", "firm.risk",
  "firm.monitoring", "firm.lifecycle", "firm.reporting",
  "firm.data.cleaning", "firm.data.etf_loader", "firm.data.manifest", "firm.data.qa",
  "firm.backtest.vector_engine",
  "firm.portfolio.forecast_combine", "firm.portfolio.sizing", "firm.portfolio.weights",
  "firm.allocation.carver_sleeve",
)
def test_live_graph_excludes_new_modules(tmp_path):
    code = (f"PREFIXES = {FORBIDDEN_PREFIXES!r}\n"
            "import sys, importlib\n"
            "for m in ('firm.runtime','firm.live.engine','firm.api.app'): importlib.import_module(m)\n"
            "bad=[k for k in sys.modules if any(k==p or k.startswith(p+'.') for p in PREFIXES)]\n"
            "print('BAD:'+','.join(sorted(bad)))\n")
    env = {**os.environ, "FIRM_DATA_DIR": str(tmp_path)}; env.pop("FIRM_AUTO_START_LIVE", None)
    out = subprocess.run([sys.executable, "-c", code], env=env, capture_output=True, text=True, timeout=120)
    assert out.returncode == 0, out.stderr
    assert "BAD:" in out.stdout.splitlines()   # exact line `BAD:` (empty list); stray logging cannot mask a failure, and a non-empty list gives `BAD:<names>` which does not match
```
- Match on exact name or `prefix + "."` so the existing `firm.agents.risk` and `firm.portfolio.optimizer` are not false positives. Do not use `startswith("firm.risk")` alone, because it would match `firm.riskfoo`.
- Also assert lazy handlers: call the lazily imported symbols (`from firm.data.pit_store import PointInTimeDataStore`, `from firm.eval.robustness import MonteCarloAnalyzer`) inside the subprocess after the main imports, then re-check `sys.modules`.
- The test must not fail for modules that do not exist yet. It lists names that may be absent; absence is a pass. P6-01 changes the forbidden list for `firm.allocation.carver_sleeve` and `firm.lifecycle.*` only through a diff the owner reviews.
Smoke script:
- Fresh interpreter, never call `IBKRBroker.connect()` or `AlpacaBroker` network methods, never load `EnvironmentFile=.env`.
- Environment reproduction: parse the `Environment=` lines of `deploy/ai-trading.service` and `deploy/ai-trading-alpaca.service` and apply them per config (for example `FIRM_LLM_CONFIG=config/llm_ab_llm.yaml` on both units, `FIRM_ENABLE_PATTERN_SCAN=1` on the Alpaca unit). Override `FIRM_DATA_DIR` with a tmp dir and drop `FIRM_AUTO_START_LIVE` and `FIRM_ALLOW_TRADING`. Assert that `firm.llm.config.llm_service_config()` resolved `config/llm_ab_llm.yaml` (not the default `config/llm.yaml`), because `build_orchestrator` wraps agents for LLM arm B through it (`runtime.py` L94-101).
- State isolation: `FIRM_DATA_DIR` does NOT redirect state paths named inside the YAML. `config/live_alpaca.yaml:604-606` sets `sp500_dynamic_universe.state_path: "data_alpaca/dynamic_universe_state.json"` (relative to cwd) and `resolve_live_startup()` (`provider_utils.py:125-130`) reads it via `load_dynamic_universe_state`. So the script runs with `cwd` set to a temp dir (or a worktree with no `data_alpaca/`) holding a COPY of the config in which every state/cache path (`state_path`, `sector_cache_path`, ...) points into the tmp dir, and it asserts only on the STATIC universe (a run from the main checkout would read live Alpaca state, which breaks the DO NOT below; a run from a worktree without `data_alpaca/` would build a different symbol list from production).
- Config build: do not call `resolve_live_startup()` then `build_orchestrator()` alone, because production builds its config in `src/firm/api/routers/live.py:_start_live_engine` (L318), which adds `"agent_modes": load_llm_config().get("agent_modes", {})` (L381); skipping that means `_maybe_wrap` never runs the LLM-enhanced agent constructors that IBKR uses. Either factor that builder out in a later LIVE-IMPORT-PATH ticket and call it, or reproduce it faithfully in the script (including `agent_modes`).
- Network isolation: set `HTTP_PROXY`, `HTTPS_PROXY` and `ALL_PROXY` together (`http://127.0.0.1:9`) AND monkeypatch `socket.create_connection` and `socket.socket.connect` to raise, because HTTPS SDKs (Groq, Alpaca) and raw TCP clients (ib_insync to :4002) do not honour a lone `HTTP_PROXY`; run under `unshare -n` when available.
- For each of `config/live.yaml` and `config/live_alpaca.yaml`: set `FIRM_LIVE_CONFIG`, build the config and orchestrator as above, and assert strategies, symbols (static universe only) and `strategy_mode` are as in the config. For the Alpaca config assert `strategy_mode == "allocation"`.
- Exit 1 on any exception. Log with stdlib `logging`, never `print` for diagnostics (CLAUDE.md rule); the final one-line verdict may be written with `sys.stdout.write`.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
Deviation register rows (each: source value, reconciled value, rationale). These are exactly the OD-16 rows:
1. G-RESEARCH 1 var_sr. Source: "SR variance across ledger trials of same family". Reconciled (matches PLAN.md section 5 and OD-16): length-adjusted cross-trial variance `var_sr_adj = max(0, var(SR_i) - mean(sampling_var_i)) + sampling_var(T_cand)`, with SR_i the per-period Sharpes of the `var_sr_family` trials, `sampling_var_i` from the Lo/Mertens SE formula at each trial's own T_i (recorded per trial in the ledger, `n_obs`), floored at the candidate grid's variance (`g_research.dsr.var_sr_rule: length_adjusted_floored_at_grid`). Unadjusted and all-family variances are reported sensitivities. Two named lists are frozen before results: `var_sr_family` (legacy `trend` standalone, alt_premia T2 and C1, S3 (5 trials), futures_trend if ever run, and all core_v1 GRID trials; diagnostic run kinds count toward N but never enter var_sr) and `prereg_family` (`core_v1`, used by gate 8). Every legacy Sharpe is converted to per-period and the conversion is recorded; pooling across different `periods_per_year` is refused (P1-03). Rationale: grid-only variance can be near zero (a degenerate grid gets no deflation, `overfitting.py` L238), and short-window legacy trials (`trend`, 491 OOS days) would inflate an unadjusted variance. Implied minimum Sharpe recorded in the register: about 1.65/yr for DSR >= 0.95 at N about 460, var_sr about 7e-4, T about 5000.
2. N rule. Source: N = effective trials incl. legacy (P1-03: gates use the max together with the raw count of legacy estimate-only trials). Reconciled and signed as an explicit DEVIATION: `N_gate = raw count (returns-bearing) + estimate-only legacy rows + counted unregistered and API-capture rows`; 463 to start (P0-05, exact, not rounded); sensitivity at 210. The effective-N estimates (ONC clusters, Meucci ENB, participation ratio, MP eigenvalue count) are all <= the raw count, so a max over them and the raw count is always the raw count; `effective_n = max(onc, enb, mp)` is therefore REPORTED AS A SENSITIVITY, not gated on. (Alternative reading, not adopted: N = max(onc, enb, mp) over returns-bearing trials + raw estimate-only rows.) `dsr()` raises rather than silently falling back to PSR(0).
3. G-RESEARCH 2. Source: PBO < 0.30, prefer < 0.20 above 20 variants. Reconciled: PBO < 0.30 via `firm.validation.pbo` at S=16, and PBO < 0.20 when the family ledger count exceeds 20 variants (counted over all trend-family trials, so it applies to core_v1). PBO is uninformative (gate 2 `insufficient`, Tier C, never a pass and never a Tier D) when the effective grid N <= 3, i.e. `effective_n` of the grid return columns (P1-03) < 4, or the median pairwise column correlation > 0.95 (`g_research.pbo.informativeness`). The pre-registered grid must vary dimensions that change the return stream (forecast cap, buffer, speed subset); tau is fixed ex ante (OD-17). Legacy `cscv_pbo` keeps S=8.
4. G-RESEARCH 3. Source: median OOS path Sharpe > 0 and >= 75% of paths > 0. Reconciled: N=10 groups, k=2, so 9 paths; require median > 0 and at least 7 of 9 positive (7/9 = 78%, since 75% of 9 is 6.75). The in-sample procedure per split is FROZEN in gates.yaml (`g_research.cpcv.in_sample_procedure`) before any result: (i) purge and embargo with `embargo_pct = 0.01`; (ii) re-estimate the P3-11 constants (forecast scalars, speed-cost filter, FDM, IDM) on the train groups only; (iii) select the grid config (forecast cap x buffer x speed subset, at most 12 configs) by train-group net Sharpe (the pre-registered argmax rule); (iv) score the test groups with that config. Without (ii) the core_v1 parameters are fixed ex ante, every path would be built from the same config's returns, and '7 of 9' would degenerate to one full-sample Sharpe > 0; selecting by argmax alone is near-arbitrary because Sharpe is roughly invariant to tau. Where step (ii) is infeasible for a constant, that constant's leakage (it saw all pre-seal data) is listed as a known limitation in the register before results. An integrity test asserts the procedure key exists; a P1-05 test asserts that CPCV paths differ when the in-sample step differs.
5. G-RESEARCH 4. Multipliers scale the full CostBreakdown (commission, fees, half-spread, impact, roll). At 2x: net Sharpe > 0 and DSR >= 0.90; 3x reported. Legacy flat-bps shown for comparison only.
6. G-RESEARCH 5. No named episode loses more than 1.5x the charter max-DD, where the reference is the pre-committed bootstrap p95 procedure, never a resettable live peak. Each episode reports active instruments.
7. G-RESEARCH 6. Source: "every free parameter" +/-25%, within 30% of chosen net Sharpe. Reconciled: perturbation is one-at-a-time, +/-25% (each direction reported); pass if the perturbed net Sharpe >= 0.7 x the chosen net Sharpe. This is ONE-SIDED, a degradation check: a perturbation that improves net Sharpe by more than 30% is not a breach (two-sided was considered and rejected). Integer-valued spans and windows are rounded half up with a minimum of 2 (EWMAC fast span 2 gives 1.5/2.5 -> 2/3; the breakout N set is rounded the same way), and the full perturbation list with direction is frozen in gates.yaml. Applied to EVERY numeric core parameter with no exemptions; list: vol span 35, the 70/30 blend, long window 2520, vol-floor percentile, EWMAC speeds and the 4x ratio, forecast cap, breakout N set and N/4 smoothing, FDM/IDM caps, buffer 0.1, tau, gross cap, speed-cost cutoff. Fraction of days at gross cap must stay <= 20% (OD-17).
8. G-RESEARCH 7. Source: after-tax, after-cost Sharpe >= passive benchmark OR correlation <= 0.3 with documented rationale. Reconciled: both branches kept, plus a mandatory power analysis (minimum detectable Sharpe gap; method pre-registered: Ledoit-Wolf 2008 studentised block bootstrap or Jobson-Korkie with the Memmel correction, paired bootstrap from P2-05, alpha 0.05, power 0.80). Decision table (`g_research.benchmark.decision_table`, each row tested in `gate_report`): (a) after-tax SR >= BM2 on the point estimate by at least the pre-set margin -> pass; (a) passes on the point estimate by less than the margin -> pass only if correlation <= 0.3 with the charter rationale, else Tier C; (a) fails on the point estimate -> pass if correlation <= 0.3 with the charter rationale, else Tier D. Benchmark BM2 = 60/40 SPY/IEF with ANNUAL rebalancing for the after-tax gate (source P2-05; monthly rebalancing realises gains more often and biases toward the candidate), monthly as a reported sensitivity, gate uses whichever has the higher after-tax Sharpe; after cost and tax (`config/tax_il.yaml` hash recorded), pre-seal data only; `core_only_100` from `docs/allocation_replay_2026_09.json` is a second reference. The live Alpaca book is excluded (post-seal).
9. G-RESEARCH 8. Mechanism section human-written and approved in `research/charters/` with a git timestamp earlier than the first ledger row carrying the `core_v1` prereg_id (`prereg_family`, which includes the P3-11 estimation trials), not the first trial of the wider `var_sr_family`; CI checks ordering. A gate 8 failure is Tier D.
10. Verdict mapping. Source: pass/fail only. Reconciled: Tier A = all 8 gates explicitly 'pass' (only this is paper-eligible); Tier D = any point-estimate failure (SR<=0, PBO >= 0.5 AND prob_oos_loss >= 0.5 (or the selected config's median OOS Sharpe <= 0), median CPCV path <= 0, net Sharpe <= 0 at 2x, stress breach, robustness breach, test 7 failing the point-estimate branch with correlation > 0.3, gate 8 failure, i.e. the charter mechanism not timestamped before the family's first trial, which is procedural); Tier C = no point-estimate failure but a confidence threshold missed (DSR<0.95, PBO >= 0.30 (>= 0.20 above 20 variants) without the Tier D conjunction, PBO uninformative (see row 3; cannot support a pass), fewer than 7 of 9 CPCV paths positive, DSR@2x < 0.90, gate 7 branch (a) passing by less than the margin with corr > 0.3, a stress episode `insufficient` below `min_active_fraction`). H4: an ENB miss is Tier D with reason "H4 ENB miss". Every gate in gates.yaml carries an explicit `point_fail` (-> D) predicate and `confidence_miss` (-> C) predicate. Any unmapped or missing gate result -> D (fail closed). Tier C and D both lead to the passive outcome, accepted in advance.
11. Charter max-DD split. Procedure fixed before any backtest: stationary block bootstrap, Politis-White block length, recorded seed, 10,000 draws, bootstrapped path length 2520 trading days (matching B0's 'expected max DD over a decade'; the p95 of max drawdown grows with horizon, so the length is frozen; full-sample length reported as a sensitivity), 95th percentile on the selected config's 1x-cost backtest; the 2.5 tau rule of thumb reported alongside. The SAME procedure gives two references: for gate 5, each episode is compared with 1.5x the bootstrap p95 max-DD over paths of that episode's own length (episode-length p95); for survival (kill switch, decommission) the reference is `survival_ref = max(p95 at 2520 days, 2.5 tau)`. RECONCILED value, not a source A9 value: source A9 says 'DD >= 20% at ~15-20% vol' (about 1.0-1.3 tau) and B0 gives 20-35% at 12-15% vol (about 1.3-2.9 tau); 2.5 tau is derived from B0's upper range and the derivation is recorded in the register. Test 5 uses the stricter episode-length bootstrap p95; kill-switch and decommission survival use `max(bootstrap p95, 2.5 tau)` so a lucky backtest cannot set a hair-trigger.
12. G-PAPER 1. Source: >= 6 months and >= 26 rebalances. Reconciled: at least 26 scheduled weekly review events (traded or not) and at least 6 calendar months, starting after the 2-week EMBARGO, on the dedicated candidate account only.
13. G-PAPER 2/3. Correlation >= 0.95 and annualised TE <= 25% of tau vs shadow replay; realised cost <= 1.5x modelled (median per trade and aggregate, commission included). G-PAPER 3 is evaluated only after at least 30 fills across at least 10 instruments; paper extends until reached.
14. G-PAPER 4/5. Position-break duration and missed reviews get durable records; a stuck working order that blocks a review counts as a missed review unless explained. All kill switches fault-injected.
15. Unseal. 12-month minimum before the one-time forward holdout; pass required before first live step (OD-18); gate: forward net SR not below the 5th percentile of the block-bootstrapped distribution of 12-month backtest SRs, and forward max-DD within the charter envelope; labelled a no-contradiction check.
16. H5. Met by a dry-run `Allocator.plan` enforcement test (P5-01). H4: ENB across asset classes >= 2.5 (ETF) or >= 3 (futures) as a hard exit; a miss stops the candidate with no post-hoc universe changes.
17. P1-08 acceptance rates, with the DGP and aggregates frozen in gates.yaml `p1_08_acceptance` BEFORE the harness is written (the harness may not be changed to pass): DGP T=2520 daily, GARCH(1,1)-t returns with frozen omega/alpha/beta/nu and cross-correlation; K=50; n_sims=500 and a master seed for size/power, each of RC, SPA and RW-FWER reported separately. Size <= 0.07 at alpha 0.05 under the global null (MC standard error about 0.0097 at p=0.05, n=500). Power (RECONCILED, matches P1-08 and OD-16): single-test PSR/t-test power >= 0.80 at K=1, annualised SR 1.0 over 10 years; multiple-testing power >= 0.80 at K=50 with the true strategy at annualised SR 1.3 (analytic Bonferroni power about 0.85), or within 0.05 of a simulated oracle max-t test on the same scenario; SR 1.0 among K=50 is a REPORTED scenario only (its power is about 0.53-0.55 for any correct implementation). PBO: MEAN PBO over 200 noise matrices lies in [0.4, 0.6]; mean PBO < 0.1 in the pinned strong-drift scenario N=30, annualised SR 3.0, T=1600, S=16, over >= 20 fixed seeds. The full scenario parameters (K, T, SR, GARCH, B, n_sims, seeds, alpha) are frozen in `p1_08_acceptance.scenarios`. Two-sided DSR calibration: with N=K and var_sr=1/T, PSR(0) of a single null series is Uniform(0,1) (KS p > 0.01), and the DSR pass rate in the strong-drift scenario is within Monte Carlo error of a simulated oracle. DSR false-pass <= 5% under a frozen null (N, var_sr and T fixed in the file).
18. G-LIVE-STEP and G-DECOMMISSION as in the plan: one trigger -> PROBATION and review; two -> target weight 0, approval to resume. Drawdown trigger > 1.5x the charter survival reference. `g_live_step`: `dd_reference: survival_ref`, `dd_multiple: 1.0` (1.5x is decommission, not pass), `min_months: 3`, G-PAPER 3 on live fills only after >= 30 fills across >= 10 instruments (P7-02). `g_paper` may carry at most one pre-declared re-evaluation date (P6-02).
19. Further frozen keys collected from tickets (each a register row): `charter.kelly_tau_bound` (`tau <= 0.5 x Kelly vol`, `enforce: true`, P4-05/P5-02); the H4 ENB method `meucci_pca_pnl_cov` on asset-class P&L covariance, stress-correlation flag threshold 0.7 and its rolling window (P4-02); the P4-03 portfolio parameters `vol_ewma_span`, `max_vol_scale` 1.5 and the 2x instrument risk-cap multiple solved by bisection (also in the gate-6 robustness list); P4-04 deviations (survival_ref floor at 2.5 tau, audited reset baseline and `record_nav_correction`, HARD and HALT block new orders rather than flatten, SOFT alert-only, settings in `config/kill_switch.yaml`); gate 5 `min_active_fraction` and the stress-period list hash (or a pointer to the core_v1 prereg if it holds them); robustness dependent-constants rule (re-estimate the perturbed rule's scalar with the P3-11 procedure) and integer rounding half-up with minimum 2; `monitoring.fidelity_window: 63` trading days and the zero-exposure-day rule (P5-04); `n_rule` text equal to row 2.
Hash rule: the sha256 is of canonical JSON of gates.yaml with the `meta` block EXCLUDED (a file cannot contain its own hash). The expected hash is stored OUTSIDE gates.yaml, in the owner-signed line of `docs/gate_deviation_register_2026_10.md` (or `research/approvals/gates_signoff.yaml`), so editing a threshold and updating a field in the same file cannot pass. The integrity test recomputes the hash and compares it with that signed value from P0, so the gates are anchored through P0-P1 (not only once P1-09 creates preregs); every new prereg stores it too.

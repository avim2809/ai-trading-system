# P1-01 — Host-level append-only hash-chained trial ledger, git mirror, legacy backfill

**Phase:** P1 **Status:** DONE (batch3/y; owner actions: commit tests/integrity draft, provision root, run real backfill+sync) **Depends on:** P0-05, P0-06 **Touches live services:** no **Owner decisions:** OD-10, OD-09 **Also depends on:** P0-04 (the `tests/integrity/` files below are owner-committed)

## Rationale (cite source plan / literature)
Source plan P1-01: every backtest must leave an immutable `TrialRecord`, because the Deflated Sharpe Ratio (Bailey and Lopez de Prado 2014) is only honest if N counts every configuration ever tried, including failures. The source specified a SQLite or Parquet file with UPDATE/DELETE triggers and `row_hash = sha256(prev_hash + row_json)`. We keep the hash chain and the insert-only rule. We change the storage, because the repo is worked on from parallel worktrees (see Reconciliation) and a per-branch file would fork. Source DoD "every backtest entry point routes through the logger" is split: this ticket builds the ledger and `backtest_logged`; P1-12 wires the entry points.

- **`ExperimentRun`/`RunRegistry`** (`src/firm/experiments/registry.py`): `config_hash` uses `json.dumps(..., default=str)`, which is lossy (two different objects can stringify equal). It also has `clear_all` and a DELETE API route, and `runs/` is gitignored and holds only 9/25-9/28 runs (38 dirs; 28 registry rows). So `runs/` cannot be the ledger. `TrialRecord` is a superset of `ExperimentRun` fields; `config_hash` is taken over canonical JSON (sorted keys, no `default=str`; unserialisable values raise).
- **Source says** `src/research/ledger.py` and `research/ledger/trials.sqlite` in the repo. **Actual:** package is `src/firm/` (`pyproject.toml` packages.find where=src; only `src/firm` exists), so code goes to `src/firm/research/`. Storage is a JSONL file, not SQLite (decision OD-10, below).
- **Returns storage policy (settled here, applies to P1-11 and P0-06).** Canonical per-trial returns parquet stay on the HOST ledger (`/local/store/research-ledger/returns/`) and travel to reviewers in the private review bundle. Git holds only `trials.jsonl` plus a returns MANIFEST (`research/ledger/returns_manifest.jsonl`: `trial_id`, `sha256`, `n_obs`). Reason: returns derived from licensed EODHD data must not be pushed to GitHub (owner practice: bundle licensed data privately; `.gitignore` re-includes only `review/**/*.parquet`). P0-06's `!research/ledger/returns/**/*.parquet` re-include is therefore NOT needed and should be dropped (cross-file item).
- **Why host-level.** Parallel agents work in separate worktrees (`.claude/worktrees/<ticket>`). A hash chain kept in a git file forks the moment two worktrees both append, and a trial run in an abandoned worktree would vanish from N. So the canonical file is `/local/store/research-ledger/trials.jsonl` (outside every worktree), written only through `firm.research.ledger` under `fcntl.flock` (the repo already uses flock in `scripts/fetch_eodhd_extras.py:98`). Per-trial returns go to `/local/store/research-ledger/returns/<trial_id>.parquet`. `chattr +a` on the file is optional and an owner action (OD-10).
- **Git mirror.** A serial step (`scripts/sync_ledger_mirror.py`) copies the canonical `trials.jsonl` into tracked `research/ledger/` and writes the returns manifest (parquet files are NOT mirrored into git, see the returns storage policy). CI (`tests/integrity/test_ledger_chain.py`) checks, for each commit, that the mirror file is a strict prefix-extension of the previous commit's mirror, that the chain verifies, and that every `returns_path` has a manifest row. `.gitignore` keeps ignoring `*.parquet` (line 20); no new re-include is needed.
- **Dirty-tree rule.** `code_commit` is the HEAD of whichever worktree/branch ran. The check ignores changes under `runs/`, `data/`, `review/`, and `research/ledger/` (these are outputs). The HARD refusal (`DirtyTreeError`) applies only to `mode="registered"`. `unregistered` and `exploratory` rows are ALWAYS recorded on a dirty tree, as `code_commit = "<sha>+dirty"` plus a `dirty_paths_digest` (sha256 of the sorted porcelain output), and are non-promotable by mode anyway. Reason: P1-12 promises that every outermost call is counted (OD-09, OD-04's accepted residual risk is mitigated by capture), and the normal exploratory case is a worktree with uncommitted changes (the main checkout is dirty right now). Freeze-then-run branches (research/eodhd-S1..S5 were run on freeze branches) are fine: `code_commit` is that branch's commit.
- **Counting rule (OD-09).** Modes: `registered` (matches an approved prereg hash, promotable), `exploratory` (counted, never promotable), `unregistered` (captured by P1-12, counted, never promotable), `legacy` (backfilled). Legacy estimate-only rows carry `count_is_estimate=true` and `n_variants`. N for DSR (computed in P1-03, not here) is about 460 to start; sensitivity at 210.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
Row format: one JSON object per line: `{"seq": n, "prev_hash": h_{n-1}, "row": {...TrialRecord...}, "row_hash": h_n}` with
`h_n = sha256(h_{n-1} + canonical_json(row))` (source formula) and `h_0 = "0"*64`. `seq` is added so a deleted line is detectable even if someone re-hashes: verify checks `seq` is 0..n-1 contiguous.

`record_trial`:
1. Validate mode rules (`registered` requires `preregistration_id`; `unregistered`/`exploratory` must have it `None`). A Sharpe without `periods_per_year` is rejected; P1-03 and P3-08 refuse to pool `var_sr` across rows with different `periods_per_year` unless converted explicitly. The legacy adapters set `periods_per_year=252` for `trial_daily_sharpes` series (daily by construction) and record the conversion in `sharpe_conversion`.
2. If `mode != "legacy"`: check dirty tree (`git status --porcelain` in the running worktree, excluding `runs/`, `data/`, `review/`, `research/ledger/`). If dirty: for `mode="registered"` raise `DirtyTreeError` (unless `FIRM_LEDGER_ALLOW_DIRTY=1`, in which case store `"<sha>+dirty"` and downgrade the mode to `exploratory`); for `unregistered`/`exploratory` NEVER raise and never require the env var: store `code_commit = "<sha>+dirty"` and `dirty_paths_digest` in `config["_provenance"]`. Rationale: the source says "refuse dirty tree" for evidence runs, but a refusal on non-promotable modes would silently drop trials from N (P1-12 catches and logs failures), contradicting OD-09 and the P1-12 promise that every outermost call is written.
3. Open ledger with `open(path, "a+b")`, `fcntl.flock(fd, LOCK_EX)`, read the LAST line only (seek from end) to get `prev_hash` and `seq`, append the new line, `flush`, `os.fsync`, release. If the returns Series is given, write the parquet to a temp name in `returns/` and `os.replace` it BEFORE appending the row, so a row never points at a missing file.
4. The ledger ROOT must already exist and be writable: `record_trial` does NOT auto-create `/local/store/research-ledger` (the non-root research user cannot mkdir under root-owned `/local/store`, and a root process creating it first would lock the research user out). It raises `LedgerNotProvisionedError` with the provisioning command in the message. Only `returns/` and the file itself are created lazily below the root.
5. Refuse the DEFAULT host root (`/local/store/research-ledger`) when `PYTEST_CURRENT_TEST` is set (raise `LedgerNotProvisionedError`-style refusal), so a test that forgot `FIRM_RESEARCH_LEDGER_ROOT` can never write the real ledger. Add `test_refuses_default_root_under_pytest`.
6. Row append is the commit point. A crash between the parquet write and the append leaves an orphan parquet, which `verify_chain` reports as a warning, not an error.

`backtest_logged` / `run_trial`: record in `finally`. On exception write `status="failed"`, `error=repr(exc)` (truncated to 2000 chars), then re-raise. This copies the pattern at `runner.py:62-82`. Failed trials count toward N.

Backfill (`scripts/backfill_legacy_trials.py`): reads `research/ledger/legacy_backfill.csv` (signed census, P0-05) and the 11 JSON files. For every JSON entry, the adapter emits one row per entry, `n_variants = entry n_trials` (for s5: `len(variant_names)`), `source_file = "docs/S1_trial_history.json"`, `source_entry_index = i`, `family` from the file's `family` key or the file stem, `count_is_estimate=false`, `config = {"fingerprint": ..., "trials": [...], "trial_daily_sharpes": [...]}`, `mode="legacy"`. pattern_ml additionally stores `config["n_configs"] = 13`-style count (sum of `n_candidates`) next to `n_variants = n_trials` (folds x candidates) so both conventions are kept. Rows from the CSV with `count_is_estimate=true` (Gann ~145, pre-ledger A/B ~20, construction ~39, pattern work before 9/25 ~20, Danelfin ~8, LLM ~6, sleeves/allocation ~10, re-runs ~5) get `source_file = "research/ledger/legacy_backfill.csv"` and `source_entry_index` = CSV row number. Idempotency: before inserting, read the existing `(source_file, source_entry_index)` set and skip duplicates; re-running appends nothing. Run order is deterministic (sorted file names, then entry index) so the ledger content is reproducible.

Sync (`scripts/sync_ledger_mirror.py`): takes the same flock, verifies the chain, then copies `trials.jsonl` to `research/ledger/trials.jsonl` and appends a manifest row (trial_id, sha256, n_obs) to `research/ledger/returns_manifest.jsonl` for each new `returns/*.parquet` (the parquet files are not copied into git). It also ingests the API capture inbox written by P1-12 (see that ticket): an idempotent ingest keyed on `(source_file, line index)`, run as an owner/ops step. Refuses if the existing mirror is NOT a byte-prefix of the new canonical file (that would mean the canonical file was truncated or rewritten). Prints the new row count. It does not `git add` or commit; the owner or serial step commits.

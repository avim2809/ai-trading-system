Methods: Lopez de Prado, "Machine Learning for Asset Managers" (2020) on the Optimal Number of Clusters (ONC); Meucci (2009), "Managing Diversification" (effective number of bets, ENB: the entropy of a PORTFOLIO's risk contributions along principal components, so it needs weights); the weightless eigenvalue-share entropy is called `effective_rank` here; Marchenko and Pastur (1967) random-matrix eigenvalue edge to separate signal eigenvalues from noise; the participation ratio. The same primitives feed the diversification report (P4-02, H4: ENB >= 2.5 for the ETF path).

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
- **Correlation:** pairwise-complete with overlap >= 250 (source). Pairs below overlap are NaN. Before eigen-decomposition, project to the nearest PSD correlation matrix (clip negative eigenvalues to 0 and renormalise the diagonal) and log the clip magnitude. Constant (zero-variance) columns are dropped and counted as raw but redundant.
- **Participation ratio:** `PR = (sum_i lambda_i)^2 / sum_i lambda_i^2` of the correlation matrix. `PR=1` for one dominant factor, `PR=N` for identity.
- **Effective rank (weightless, trial counting):** `p_i = lambda_i / sum lambda`; `effective_rank = exp(-sum p_i ln p_i)` (0 ln 0 := 0). This is the eigenvalue-share entropy; it is NOT Meucci's ENB. Noise eigenvalues add entropy, so it overstates k (in the planned-block design about 1.5k).
- **ENB (Meucci 2009, weighted):** with eigenvectors `e_i` and eigenvalues `lambda_i` of `cov`, the principal-portfolio risk contributions are `p_i = (e_i' w)^2 lambda_i / (w' cov w)` and `ENB = exp(-sum p_i ln p_i)`. It needs `weights`: a portfolio concentrated in one asset class must score low even when the correlation structure is diverse. P4-02's H4 hard exit (ENB >= 2.5 across asset classes) MUST call this with the actual asset-class weights, not `effective_rank`. The minimum-torsion variant is optional (`min_torsion`), documented, not used by the gate.
- **Marchenko-Pastur edge:** for `q = N/T` and noise variance `sigma2` (1 for a correlation matrix), `lambda_plus = sigma2*(1+sqrt(q))^2`. `n_signal_eigenvalues` counts eigenvalues above `lambda_plus`; effective N by method `mp_eigen` = `max(1, n_signal)`, i.e. the number of signal factors (reported; the noise block is treated as redundant, not as independent trials). Document the choice and that it is the least conservative of the three.
- **ONC (Lopez de Prado):** distance `d_ij = sqrt(0.5*(1 - rho_ij))`; for each `k` in 2..max_k run k-means on the correlation rows (n_init restarts, fixed seed), score by the silhouette-based quality `q_k = mean(silhouette)/std(silhouette)`; choose k maximising `q_k` (with the base-clustering refinement step of ONC optional but documented; the simple version is acceptable if tests pass). `effective_n(..., "onc") = number of clusters`. ONC searches k in 2..max_k, so special-case k=1: if all off-diagonal |rho| exceed a stated threshold (default 0.95) return 1 before clustering.
- **Gate usage:** report all three plus raw; `gate_n` = `max(effective_onc, effective_enb, effective_mp, raw_returns_bearing) + legacy_ledgered + legacy_estimate + failed_or_no_returns + unregistered + api` (source: "gates use the max together with raw count of legacy estimate-only trials"; the legacy ledgered and failed buckets are added per OD-09). `sensitivity_ledger_only` = ledger-only count (210) for the report. Never choose the smallest N (source DO NOT).
- **Fisher-z:** `z = (atanh(r1) - atanh(r2)) / sqrt(1/(n1-3) + 1/(n2-3))`, two-sided p from the normal CDF (use `firm.eval.overfitting._norm_cdf`); `bh_adjust` is Benjamini-Hochberg (can reuse P1-07's `benjamini_hochberg`).

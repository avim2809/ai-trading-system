## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
Source algorithm kept: split rows (time order preserved) into S contiguous blocks; for each of the C(S, S/2) combinations take IS = those blocks, OOS = the rest; `n* = argmax_n metric(IS)`; OOS relative rank `omega_bar = rank(OOS metric of n*) / (N+1)`; `lambda = ln(omega_bar / (1 - omega_bar))`; `PBO = P(lambda <= 0)`; degradation: regress OOS metric of `n*` on IS metric of `n*` across splits and report the slope.

Differences, each deliberate:
- **Ties:** rank with AVERAGE ranks (e.g. `scipy.stats.rankdata(method="average")`, scipy is a declared dependency). Legacy ranks by argsort order, so on ties the two functions diverge. A test documents the divergence.
- **`argmax` ties in IS:** choose the lowest column index deterministically and record nothing random.
- **Clamp:** `omega_bar` is clipped to `[1e-6, 1-1e-6]` like legacy to keep logits finite.
- **Tail rows:** `truncate_tail` drops the last `T % S` rows (same as legacy, so equivalence holds when `T % S == 0` and is exact otherwise) and reports `rows_dropped`; `tail="raise"` refuses non-divisible T. The policy is stated in the docstring and in the result so a report can show it. No row shuffling, ever.
- **No 0.5 sentinel:** `T < 2S` or `N < 2` raises `ValueError`; `N < 4` sets `uninformative=True`.
- **embargo_pct:** supported with the same semantics as legacy (trim OOS edges adjacent to IS blocks) to allow an equivalence test with embargo; default 0.0 as the source (no embargo in CSCV).
- `metric` is a vectorised column function (default Sharpe), so P3-08 can pass a Sortino or other metric. The family test uses the default.

## Tests & acceptance criteria (concrete test file names and assertions)
`tests/test_pbo.py`:
- `test_noise_gives_half`: 20 seeded noise matrices (T=1600, N=10..30, S=16): mean PBO in 0.5 +/- 0.1 (source test).
- `test_strong_drift_gives_low_pbo`: PINNED design, asserted on the MEAN over >= 20 fixed seeds (not a single seed, no seed-picking): N=30, annualised SR 3.0, T=1600, S=16 (scratch: mean PBO 0.001, max 0.014), and N=10, SR 2.5 (scratch: mean 0.004, max 0.071); assert mean PBO < 0.1. The source's `SR about 1.5, N=10..30` is NOT a pass bar: scratch runs give mean 0.06 to 0.10 with seeds up to 0.39, which is flaky; keep it as a reported (non-asserted) scenario.
- `test_equivalence_with_cscv_pbo_tie_free`: tie-free random matrices, `embargo_pct=0`, `T % S == 0`, S in {8, 16}: `pbo(M, S).pbo == cscv_pbo(M, S)` to 1e-12. A property-style loop over 30 seeds.
- `test_divergence_on_ties_documented`: matrix with several identical zero columns; assert the two values differ in a stated direction/tolerance or at least that `pbo` is invariant to column permutation while `cscv_pbo` is not.
- `test_permutation_invariant_in_columns` for `pbo`.
- `test_reversal_symmetry`: when `T % S == 0`, `pbo(M).pbo == pbo(M[::-1]).pbo` exactly. This is a TRUE invariant (block k maps to block S-1-k, the set of combinations is closed under that map, Sharpe ignores order within a block; scratch: equal for all 5 serially-correlated seeds), NOT a shuffle detector. The earlier spec ("reversal changes PBO") would fail on a correct implementation.
- `test_blocks_are_contiguous` (the working no-row-shuffle guard): build a matrix where column j is good only in rows of a known block set; compare the exact per-split `logits` with a naive `itertools.combinations` reference that uses explicit contiguous slices. Any internal permutation of rows breaks the exact match. Comparing against a row-shuffled INPUT proves nothing (it differs whether or not the implementation shuffles) and is not used.
- `test_naive_reference_matches`: a slow pure-python reference (itertools.combinations, `np.argsort`-based average ranks) agrees to 1e-12 for S=8; if `pypbo` is importable, `test_pypbo_agreement` asserts |diff| <= 0.02 (source test), else skipped with reason.
- `test_degradation_slope_sign`: slope < 0 under noise; under strong drift (the pinned design above) assert `prob_oos_loss < 0.1` and the mean OOS Sharpe of `n*` > 0. Do NOT assert a positive slope under drift: IS and OOS are complementary halves of the same column, so when the drift column is mostly selected the OOS metric regresses NEGATIVELY on IS (scratch: slope about -0.8, 0% of seeds positive).
- `test_prob_oos_loss_range`, `test_tail_policy` (`truncate_tail` equals manual truncation; `raise` raises), `test_small_inputs_raise`, `test_uninformative_flag_for_N_lt_4`.
- `test_runtime_budget`: S=16, T=2500, N=50 completes in < 30 s on the test host (marked slow, run niced).

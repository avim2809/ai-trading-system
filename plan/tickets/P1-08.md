# P1-08 — Synthetic GARCH-t validation harness (size/power at pre-set rates)

**Phase:** P1 **Status:** NEW **Depends on:** P0-08, P1-01, P1-02, P1-03, P1-04, P1-05, P1-06, P1-07 **Touches live services:** no **Owner decisions:** OD-16

## Rationale (cite source plan / literature)
Source plan P1-08: before any real-data research, prove the whole statistics pipeline (ledger, DSR, PBO, CPCV, RC/SPA/Romano-Wolf) has the right false-positive rate and enough power on synthetic data whose truth is known: heavy-tailed, volatility-clustering returns (GARCH(1,1) with Student-t innovations; Bollerslev 1986; Bollerslev 1987 for t errors) with an optional injected trend (autoregression at 1-12 month horizons) or carry. This is the H1 evidence in the phase exits. Source DoD: a dated markdown report.

```python
@dataclass(frozen=True)
class GarchTParams:
    omega: float = 5e-6; alpha: float = 0.05; beta: float = 0.90; nu: float = 6.0; mu: float = 0.0   # unconditional daily vol sqrt(5e-6/0.05) = 1%
    def finite_fourth_moment(self) -> bool: ...   # beta^2 + 2*alpha*beta + kappa*alpha^2 < 1, kappa = 3(nu-2)/(nu-4); defaults: 0.81+0.09+6*0.0025 = 0.915
STRESS_PARAMS = GarchTParams(omega=1e-6, alpha=0.08, beta=0.90, nu=5.0)   # documented stress scenario: fourth moment INFINITE (0.81+0.144+9*0.0064 = 1.0116), unconditional vol about 0.71%

def simulate_garch_t(n: int, params: GarchTParams, seed: int, burn: int = 500) -> np.ndarray
    # r_t = mu + sigma_t * z_t, z_t ~ standardised Student-t(nu) (unit variance),
    # sigma_t^2 = omega + alpha*(r_{t-1}-mu)^2 + beta*sigma_{t-1}^2
```

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
- **GARCH-t generator:** standardise the t draws to unit variance (`z = t_nu * sqrt((nu-2)/nu)`, needs `nu > 2`); initial `sigma^2` at the unconditional variance `omega/(1-alpha-beta)` (require `alpha+beta < 1`); discard `burn` observations. Daily defaults give 1% daily vol and a finite fourth moment (PSR/DSR take sample kurtosis as an input, which is inconsistent when the fourth moment is infinite); the infinite-kurtosis `STRESS_PARAMS` run only as a separate documented stress scenario next to the finite-kurtosis baseline.
- **Injected trend (source: "AR at 1-12 month horizons"):** add a predictable component `phi * s_{t-1}` where `s_{t-1}` is the sign/return of the past `horizon_days` (21..252) window, with `phi` solved by bisection so the strategy "go long when past return positive" has the target annualised Sharpe in expectation (verified inside the unit test by a large-sample estimate).
- **Injected carry:** add a slowly varying predictable mean (AR(1) with half-life about 60 days) scaled to the target Sharpe.
- **Scenarios (source: "run ledger -> DSR -> PBO -> CPCV -> RC"):**
  1. `null`: K=50 independent GARCH-t series, no signal. Statistics: RC, SPA and Romano-Wolf family-wise rejection rate (size, target <= 0.07 at alpha 0.05); DSR false-pass rate for the best of K (target <= 5% at DSR >= 0.95); PBO on the T x K matrix (target 0.5 +/- 0.1). Two-sided DSR calibration (PLAN.md G-RESEARCH 1, P0-08 row 17): with N=K and var_sr=1/T, PSR(0) of a single null series is Uniform(0,1) (KS p > 0.01); in the strong-drift scenario the DSR pass rate is within Monte Carlo error of a simulated oracle.
  2. `drift`: scenarios and bars as re-stated in the Reconciliation (single-test power K=1 at SR 1.0/10y; multiple-testing power at K=50, SR 1.3 (or within 0.05 of the simulated oracle) with the analytic power recorded, K=10 at SR 1.5 reported; PBO < 0.1 at N=30, SR 3.0, T=1600). Also reported, not pass bars: SR 1.0 among K=50 (power, PBO, DSR pass rate, CPCV positive-path count).
  3. `trend` and `carry`: same with injected structure, to confirm the pipeline is not accidentally tuned to iid drift.
  4. `autocorrelated null`: AR(1) rho 0.3 noise to confirm block-bootstrap procedures keep size where an iid control over-rejects (documented control).
- **Plumbing check:** at least one scenario routes through the REAL ledger code (throwaway root): `record_trial` for each of K strategies, `trials()`, `gate_n`, then the stats, so the integration (not just formulas) is validated. Per-sim seeds are `seed + sim_index`; results are bit-reproducible.
- **Pass/fail:** `evaluate` compares each measured rate with the frozen `gates.yaml` bar; with Monte Carlo error on 500 sims reported as a Wilson interval next to each rate. The verdict line is PASS only if every bar is met on the point estimate; borderline (point passes, upper CI fails) is flagged "marginal" and listed for the owner, not silently passed.
- **Report:** markdown with parameters, git commit (clean tree required), `gates.yaml` hash, seeds, runtime, resource use, all rates with CIs, failures, and the explicit sentence "Harness thresholds were read from gates.yaml frozen at <hash>; none were changed after viewing results."

## Tests & acceptance criteria (concrete test file names and assertions)
`tests/test_synthetic.py` (fast, <30 s):
- `test_garch_unit_variance_and_fat_tails`: standardised innovations have variance within 3% of 1; kurtosis of simulated returns exceeds 3 (excess > 1 for nu=5); squared-return autocorrelation at lag 1 is positive (volatility clustering).
- `test_garch_stationarity_guard`: `alpha+beta >= 1` raises.
- `test_default_params_finite_fourth_moment`: `GarchTParams().finite_fourth_moment()` is True (0.915 < 1) and `STRESS_PARAMS.finite_fourth_moment()` is False; unconditional daily vol of the defaults is 1% within 3%.
- `test_run_scenario_takes_parameters_only_from_spec`: `run_scenario` has no K/T/SR/seed/B literal; changing the loaded spec changes the output, and the CLI refuses overrides that differ from the frozen block (except `--quick`, which marks the report non-evidence).
- `test_inject_trend_hits_target_sharpe`: simple trend rule realised annualised SR within 0.15 of target on a 200k-obs series.
- `test_inject_carry_hits_target_sharpe`, `test_make_universe_correlation`.
- `test_seed_reproducible`.
- `test_evaluate_reads_thresholds_from_gates_yaml` (monkeypatch gates path; changing the file changes the verdict, and there are no numeric thresholds as literals in `synthetic.py`: a static grep test fails on literals `0.07`, `0.80`, `0.05` outside docstrings or the CLI defaults for alpha).
- `test_quick_smoke_runs_end_to_end`: `--quick` with tiny sims runs, writes a report to `tmp_path` labelled non-evidence, leaves the host ledger untouched (uses `FIRM_RESEARCH_LEDGER_ROOT` temp).

Acceptance (H1): the full run (the frozen `n_sims`, 500) on the research host completes; the report shows every `gates.yaml` bar met on point estimates, OR lists failures and the owner decides which module to fix (new commit, rerun, new dated report; the failing report is kept in `research/validation/`).

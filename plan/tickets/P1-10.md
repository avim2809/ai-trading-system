## Rationale (cite source plan / literature)
Source plan P1-06/P1-07: autocorrelated returns must not be resampled iid. `MonteCarloAnalyzer.bootstrap_returns` is iid, so Sharpe CIs and drawdown tails are understated for trend or low-turnover sleeves (Politis and Romano 1994; Lahiri 1999 on block bootstrap for dependent data). The charter max-DD procedure (P5-02) uses a stationary bootstrap with Politis-White block length, and G-DECOMMISSION reuses it.

A merge to main is a deploy on next crash/restart/lazy import.
- **Design:** add `method="iid" | "stationary"` (default `"iid"`) and `block_len: float | None` to `bootstrap_returns` (and thread them through the constructor so `summary()` and the CI helpers can use them). The `"stationary"` branch does a LAZY import of `firm.validation.bootstrap` inside the branch only. The default path executes exactly the old lines, in the same RNG order, so outputs are bit-identical.
- `firm.validation.bootstrap` must stay un-imported by default: P0-06's isolation test forbids `firm.validation.*` in the live import graph (a lazy in-function import never loaded at startup is fine: the test imports `firm.live.engine`, `firm.api.app`, `firm.runtime` and checks `sys.modules`).
- Seed handling: the stationary branch derives its seed from `self._rng.integers(0, 2**32)` so a single constructor seed still controls everything and the iid RNG stream is not perturbed when method is `"iid"`.
- Existing tests: `tests/test_robustness.py` (also exercised via `tests/test_capital_gate.py`). They must stay green unmodified; new tests are appended.

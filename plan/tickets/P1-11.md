## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
1. For each dir in `RESEARCH_DIRS` that exists: walk files, sha256 each, copy files <= `GIT_LIMIT` to `review/research/<same relative path>`; files > limit go to the bundle pairs with `location="bundle:<arcname>"`. Also walk `<ledger_root>/returns/*.parquet` (host ledger, default `/local/store/research-ledger`) and add each as a bundle pair with arcname `research_ledger_returns/<name>` and an index row (sha256, rows); none of them are copied into `review/`. `main()` passes the pairs to `make_bundle(..., extra=pairs)`. Reuse `sha256()` and `_git_safe()`; add `research/` rows with `study="research_infrastructure"`.
2. `research_verification()` imports `firm.research.ledger.verify_chain` and `firm.research.prereg.verify_index` (script runs in the worktree venv, where `firm` is importable; if the import fails log WARNING and write `{"error": ...}` so the package build does not silently omit verification). Includes `git_head` and UTC time from `datetime.now(timezone.utc)`; never local time.
3. Records `gates_yaml_sha256` and the count of ledger rows by `mode` (registered, exploratory, unregistered, legacy) and the legacy total (must be >= 210 and equal the signed census) so a reviewer sees N composition at a glance.
4. README addition: `review/README.md` is hand-written today; this ticket does not rewrite it, but `main()` writes `review/research/README.md` explaining how to verify the chain (`python -c "from firm.research.ledger import verify_chain; ..."`) and the prereg fingerprints (recompute command).
5. Idempotent: re-running overwrites `review/research/` deterministically (sorted walk).

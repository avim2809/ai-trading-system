## Rationale (cite source plan / literature)
Source plan P1-01 DoD: "every backtest entry point routes through `backtest_logged`", and its rule that exploratory runs are counted. Without this, any run made outside a registered harness is invisible to N, and the Deflated Sharpe Ratio (Bailey and Lopez de Prado 2014) is understated. This ticket captures every run with a cheap hook, counts it, and never lets it become promotable evidence. It was split out of P1-01 because it edits live-imported modules and therefore needs the deploy protocol.

- **Double counting hazard:** `ExperimentRunner.run -> _execute_backtest -> execute_backtest` is one logical run. A re-entrancy guard (a `contextvars.ContextVar` depth counter in the capture module) ensures only the OUTERMOST wrapped call records. Walk-forward with N folds and K candidates records N fold rows (each fold is an outermost `ExperimentRunner.run`, config key `_walk_forward`) PLUS N*K train-window candidate rows (each an outermost direct `execute_backtest` call at `runner.py:342`, `entry="execute_backtest"`). All of them are real backtests and ALL count toward N. No ticket dedupes by `config_hash` in a way that lowers N; P1-03's `gate_n` counts every row. `run_walk_forward` is not wrapped (file list stays `ExperimentRunner.run` only); analysts can group rows via `config["_walk_forward"]["fold"]`.
- **Live-import graph (why this is LIVE-IMPORT-PATH):** `runtime.py` is imported at module top by `firm/live/engine.py`; `execute_backtest` is lazily imported inside API request handlers (`api/jobs.py:92`). Any merge to main touching these is a deploy on the next crash, reboot or lazy import, because both services (IBKR :8000, Alpaca :8001, `Restart=always`) import from this checkout. Therefore: self-contained edits, no new cross-module symbols that already-loaded modules would need (the 9/28 version-skew ImportError class), and the protocol in Definition of done.
- **Fail-safe by default: the hook never imports `firm.research` unless a research process has ARMED it.** The previous design (an `IN_API_PROCESS` flag that selects the stdlib path) was fail-open across the merge-to-restart window: inside a running firm-api, `firm.backtest.run` and `firm.experiments.runner` are loaded lazily by `api/jobs.py` handlers (L71, L92, L106), so after a merge the still-running service has the OLD `app.py` (flag never set) but lazily loads the NEW `run.py`, and would take the ledger path in the live process (git status on the live checkout, root write into the ledger, `DirtyTreeError`). The 9/28 version-skew class. So the default is inverted:

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
```
capture_run(entry, config, seed):
    depth = _DEPTH.get(); _DEPTH.set(depth+1)
    try: yield cap
    except BaseException as e: cap.error = repr(e); cap.status="failed"; raise
    finally:
        _DEPTH.set(depth)
        if depth == 0:                       # outermost only
            try:
                if LEDGER_SINK is not None:                         # armed by a research process
                    LEDGER_SINK(...)                                # -> ledger.record_trial(mode='unregistered')
                else:                                               # DEFAULT, incl. every firm-api process
                    _append_inbox_json_line(tag=('api-'+port) if IN_API_PROCESS else 'proc-'+host, ...)   # stdlib only
            except Exception: log.warning("trial capture failed (backtest result unaffected)", exc_info=True)
```
- `config_hash` for the API line is `sha256(json.dumps(config, sort_keys=True, separators=(",",":"), default=repr))`; the ledger-side hook recomputes with the strict canonical function and stores both if they differ (the API stream is lossy by design and marked so).
- Returns: if the report exposes a daily-returns series, pass it so P1-03 can compute effective N; otherwise `returns_path=None` and the row counts as a raw trial.
- Nothing is sampled or filtered: every outermost call is written, INCLUDING runs from a dirty worktree (the ledger records them as `<sha>+dirty`, P1-01); capture never relies on `FIRM_LEDGER_ALLOW_DIRTY`. Disk growth is bounded (one line per backtest).
- The ledger writer additionally refuses the DEFAULT host root when `PYTEST_CURRENT_TEST` is set (belt and braces behind the conftest fixture; implemented in `firm.research.ledger`, P1-01).
- A trial recorded by the hook can never be promoted: mode is `unregistered`, and P1-09 only accepts `registered` rows with a verified prereg hash.

## Definition of done
LIVE-IMPORT-PATH protocol, all five steps:
1. Self-contained change: only local imports inside the wrapped functions; no new symbol that an already-loaded module must find in a module that may be old.
2. Full suite passes in the worktree venv.
3. `scripts/live_import_smoke.py` passes.
4. Merge only in a window the owner acknowledges, outside the 09:15 ET planning cycle and both rebalance windows (Alpaca allocation review; IBKR cycles). Because the hook is fail-safe when unarmed, a service that keeps running OLD `app.py` after the merge is safe (it only ever writes the stdlib inbox line); an owner-run restart of both units is still recommended in the same window so the `api-<port>` tag is set.
5. Verified after the restart: owner (or ops session) checks `GET /api/live/capital-gate` (router prefix `/live` mounted under `/api`) still answers, `data/logs/api.log` and `data_alpaca/logs/api.log` (`$FIRM_DATA_DIR/logs/api.log`) show no ImportError, and that a UI backtest produces one line in `/local/store/research-ledger/inbox/api-<port>.jsonl`.
The agent does not restart services. Owner provisioning of the ledger root and `inbox/` (P1-01) must precede the merge.

## DO NOT
- Import `firm.research` (or pandas-heavy ledger code) at module top in any live-imported file, or inside the firm-api process (the hook takes the ledger path only when armed by `firm.research.capture` having been imported by a research harness).
- Rely on `IN_API_PROCESS` for safety (it is a tag), or set it in `create_app()`'s body or at import time.
- Write the capture stream under `$FIRM_DATA_DIR` or any live data dir.
- Let capture depend on `FIRM_LEDGER_ALLOW_DIRTY` or silently drop dirty-tree runs.
- Let capture failure change, delay, or fail a backtest.
- Record nested calls twice, or sample/skip runs.
- Edit the frozen `scripts/*_preregistered*.py`, or any `scripts/run_*.py` allowlisted frozen script.
- Run, restart or `systemctl` anything; edit `config/live*.yaml`.

## Rationale (cite source plan / literature)
Not in the source plan. The repo's own docs require a frozen cleaning v3 before any further EODHD-based test: stage S4 found a constant `999999.9999` sentinel in `adjusted_close` that v2 passes through (`scripts/run_eodhd_s4_evaluation.py` L65 and L1041; `docs/eodhd_shortlist_verdict_2026_10.md` L48-53; `docs/PROJECT_CONTEXT.md` L1320). A series pinned at that value produces zero or garbage returns. Source P2-03 also says negative prices are legitimate for futures (crude, April 2020), which v2's `drop_nonpositive_or_missing_price` rule would delete.

## Repo reconciliation (what exists today, exact paths+line refs, what changes vs source plan and why)
- `scripts/eodhd_clean.py` holds `CLEANING_RULES` v2 (L52, frozen `2026-09-30T18:23:17Z`), `cleaning_fingerprint()` (L66), `_spikes_and_breaks()` (L70), `clean_bars(d, asset, calendar)` (L97; asset in `equity|crypto|nav`) and `equity_calendar()` (L135). Frozen preregistrations pin `cleaning_fingerprint()`, so this file must never change.
- `tests/test_eodhd_clean.py` covers v2 (phantom holiday, spike reversal, segment break, nav, bad inputs). It stays untouched and must stay green.
- v2 rules to inherit unchanged in v3: spike reversal (`jump_up` 1.0, `jump_down` -0.5, revert within 5 bars, band 0.25), segment break at up-jump 1.5, down-jumps kept, equity calendar from SPY's `etfs_full` dates (v3 receives them as an argument; v2's raw `pd.read_parquet` at `scripts/eodhd_clean.py` L138 is not copied), crypto = all days.
- New in v3: (1) constant-sentinel rule: drop bars where any price column equals `999999.9999` (tolerance 1e-6), and drop any run of >= 5 identical `adjusted_close` values equal to a value >= 1e5 on assets whose median price is < 1e4 (report counts separately); (2) `asset='futures'` relaxes the non-positive price rule (negative and zero prices kept, but NaN dropped) and uses no equity calendar; (3) every drop is counted per rule in the report dict, as in v2.
- Source places no cleaning code; the plan says `src/firm/data/cleaning.py`. `src/firm/data/` is a live-imported package for other modules, but a new file there is not imported by anything live (P0-06 isolation test lists `firm.data.cleaning` as forbidden for the live graph).
- Spike rules on futures series: spike-reversal is applied to the level series for futures only if prices stay positive; for series with non-positive values it is applied to differences (documented, tested). This is a pre-registered choice, not tuned.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
```
validate asset; copy; parse date; sort; drop dup dates; to_numeric on OHLCV
sentinel = (px.sub(999999.9999).abs() < 1e-6).any(axis=1);  drop; rep["sentinel"]
if asset != "futures": drop non-positive/NaN price (v2 rule)   else: drop NaN only
volume rule as v2 (skipped for nav; for futures: drop NaN volume only, zero volume kept)
calendar rule as v2 for equity/nav
constant-run rule on adjusted_close (see above); rep["constant_run"]
spikes_and_breaks as v2 (copy the function body; do not import from scripts/)
```

## Rationale (cite source plan / literature)
Source plan P3-02 and A3 (trend following, strong/moderate evidence). Moskowitz, Ooi and Pedersen (2012) and Hurst, Ooi and Pedersen (2017) document time-series momentum, and Carver's EWMAC continuous forecast is the chosen implementation. A continuous, vol-normalised forecast lets sizing (P3-06) and risk limits (P4-03) work on one common scale (average absolute forecast 10, cap 20). Speeds are chosen by turnover cost only, never by performance. That is the source's central anti-overfitting rule for this ticket.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
Source formulas, kept: `raw = (EWMA_fast - EWMA_slow) / sigma_price`; forecast `= raw * scalar`, capped at +/-20; speeds (2,8), (4,16), (8,32), (16,64), (32,128), (64,256) with slow = 4*fast; scalars pooled across instruments so that the average |forecast| = 10, fixed, never per-instrument, never tuned for performance; drop speeds whose turnover cost exceeds the speed limit (annual cost above 1/3 of the expected rule Sharpe).

Additions and clarifications, each with a reason:
- `sigma_price` is the price-unit daily vol from `firm.signals.vol.price_unit_vol` (`price*vol/16`). It must be the vol known at t. The forecast is computed at close t and traded at t+1 by P3-09.
- `EWMA_*` use `ewm(span=n, adjust=False)`. NaN prices are skipped, not filled.
- The speed-selection rule is the source's, but the source's "expected rule Sharpe" is ambiguous. If it were measured on the research backtest it would be performance fitting. The design therefore requires `expected_rule_sharpe` to be a PRE-REGISTERED constant (the charter's haircut expected Sharpe, P5-02, at least a 50% haircut). It is never computed from backtest P&L. Turnover is computed from the forecast series, which is not a performance measure. `speed_cost_sharpe = turnover * cost_per_trade / sigma_pct`, where the cost per trade comes from P2-04. This is the author's reading of the source rule, flagged for owner review.
- RECONCILED: long/flat floor placement. The design's ETF path is long/flat, but flooring EACH rule before combining is not the same as flooring the combination: rules at -10 and +10 would give a per-rule-floored long position of 5*FDM versus 0 when combined then floored. That would build a systematic long bias and make the FDM (estimated from signed forecast correlations in P3-11) wrong. So per-rule forecasts stay signed (floor=-20) in the ETF path and only the combined forecast is floored at 0 (P3-05 `combine_forecasts(floor=0.0)`). The `floor` parameter here stays available for the signed futures variant and diagnostics.
- RECONCILED: the speed filter is applied PER INSTRUMENT, as in the source ("per instrument"). Per-trade costs differ a lot between ETFs (SPY versus a thin linker or high-yield ETF), so one global filter would keep too-fast speeds on expensive instruments or drop usable speeds on cheap ones. `select_speeds` returns `dict[instrument, list[speed]]`.
- The pooled scalar is estimated on the uncapped, unfloored signed raw forecast, so mean |f| = 10 holds exactly before the cap. Capping and combining happen after.
- The pooled scalar is estimated once, on the research window only, with `estimate_pooled_scalar(start, end)`. A function guard raises `ValueError` if `end` is later than `config/research_freeze.yaml`'s `max_research_date` when that module is importable. In this ticket the guard is a simple `end` argument check with no `firm.research` import, to keep the signal package self-contained. The seal itself is enforced by `data_access` in P3-11.

## Tests & acceptance criteria (concrete test file names and assertions)
`tests/test_signals_ewmac.py` (synthetic data only):
- `test_sign_on_synthetic_trend`: a deterministic uptrend gives forecast > 0 after the burn-in, a downtrend gives < 0, and a flat series gives about 0.
- `test_cap`: a huge step makes `abs(forecast) <= 20` everywhere, and the `floor=0.0` parameter gives `min(forecast) >= 0` (parameter works; the ETF path does not use it per rule).
- `test_slow_is_4x_fast_default`: `slow=None` equals an explicit `4*fast`.
- `test_pooled_scalar_gives_avg_abs_10`: on 8 synthetic instruments with different vols, the pooled scalar makes the pooled mean |raw*scalar| (uncapped, unfloored) equal 10 within 1e-9 over the window. A second assertion reports the post-cap mean |f| separately (<= 10). The per-instrument means differ (proves the scalar is pooled, not per-instrument).
- `test_scalar_uses_only_research_window`: appending 500 extreme post-window rows does not change the estimated scalar. Passing an `end` beyond the data raises.
- `test_no_lookahead`: forecast at k is identical when computed on `price[:k+1]`.
- `test_speed_selection_per_instrument`: two instruments with different `cost_per_trade` and `sigma_pct` get different surviving speed sets, and the result is keyed by instrument.
- `test_speed_selection_by_cost_only`: given fixed turnover and cost inputs, `select_speeds` keeps exactly the speeds under the 1/3 limit for each instrument. Changing `expected_rule_sharpe` changes the set monotonically. The function signature has no return/P&L argument (asserted with `inspect.signature`).
- `test_turnover_monotone_in_speed`: on a random-walk fixture, turnover is decreasing across the six speeds.
- `test_import_light` (subprocess): no `firm.live`, `firm.api`, `firm.runtime`, and no `firm.research` import.

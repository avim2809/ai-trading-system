## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
```
1. verify: prereg frozen & approved (INDEX.yaml), gates.yaml hash == prereg hash, stress_periods.yaml sha256 == prereg value, constants addendum hash OK,
   instrument-weight vector hash == the hash in constants.json (else FAIL), charter mechanism commit earlier than first ledger trial,
   seal preflight (see Operational) passed, data_access fail-closed. Any failure is a STOP.
2. build grid (<=12) from the prereg; run each config through the P3-09 engine at 1x cost; each is a ledger trial.
3. matrix M (T x N) of net returns -> CPCV (P1-05): 9 paths; PBO (S=16, P1-04); selection = pre-registered rule
   (prereg names the rule, e.g. highest in-sample DSR-free Sharpe among grid; no peeking).
   RECONCILED: in EVERY one of the C(10,2)=45 splits the selection rule is re-run on the 8 purged and embargoed TRAIN groups, and the chosen config's returns on the 2 test groups fill the 9 paths; path Sharpes come from those. Without this, a grid of fixed configs has the same test returns in every split, all 9 paths equal the full-sample series, and gate 3 collapses to 'full-sample SR > 0'.
   PBO informativeness (pre-registered before results): besides grid N <= 3, PBO is marked 'uninformative' (gate 2 `insufficient`, Tier C, never a Tier D failure) when `effective_n` of the grid columns (P1-03) < 4 or the median pairwise column correlation > 0.95, because leverage-only variants (tau, a cap that rarely binds) are near-duplicate columns and the IS-best config's OOS rank is then close to random.
4. DSR: sr = per-period Sharpe of selected; N = `firm.validation.effective_trials.gate_n` (disjoint-bucket TrialCount, P1-03) and var_sr = `length_adjusted_var_sr` over the `var_sr_family` rows (P1-02), refusing to pool rows with different `periods_per_year` (P1-01/P1-03), per gates.yaml (see Repo reconciliation);
   dsr(sr, n_obs, skew, kurt, N, var_sr) from firm.validation.sharpe_stats; sensitivity at N=210 and all-family var.
5. Cost stress 1x/2x/3x via the engine's stress_multiplier (full CostBreakdown scaling); net Sharpe, DSR@2x. A comparison-only row at the legacy flat-bps convention is also shown (design G-RESEARCH 4), run through a `FlatBpsCostFn` and logged as `kind='comparison'`; it never enters a gate.
6. Stress suite (P3-07) with the reference per episode = bootstrap p95 max-DD over paths of that EPISODE's length (P5-02 `max_dd_procedure`, stationary bootstrap with Politis-White block; OD-16 split rule); the 2520-day p95 (10 years, matching source B0 'expected max DD over a decade') is the survival reference and is recorded beside it in results.json. Any episode that is unusable, not applicable or below the pre-registered `min_active_fraction` makes gate 5 `insufficient` (Tier C), never `pass`.
7. Robustness: perturb EVERY numeric core parameter +/-25% (list in gates.yaml); net Sharpe within 30%.
   Dependent constants (pre-registered before P3-11): for each perturbation, re-estimate the scalar(s) of the perturbed rule on the same window with the P3-11 procedure (imported from the P3-11 driver), so the pooled average |f| is 10 before the Sharpe is computed; hold the speed-filter result, FDM and IDM fixed unless the perturbed parameter is one of their own inputs. Integer parameters round half-up with minimum 2, per gates.yaml (P0-08 row 7; 35 x 0.75 = 26.25 -> 26, EWMAC fast span 2 -> 2/3). A test checks a perturbed speed's pooled average |f| is 10.
   Gross-cap-bound share <= 20% (OD-17), from the `gross_cap_bound` flags passed to the engine.
8. Benchmark: after-tax, after-cost vs BM2 (P2-05); correlation to BM2; power analysis. Pre-registered method (gates.yaml/prereg, before results): Sharpe-difference test for correlated returns (Ledoit-Wolf 2008 studentised block bootstrap, or Jobson-Korkie with the Memmel correction), alpha=0.05, power 0.80; 'underpowered' means the minimum detectable Sharpe gap at that power exceeds the |observed SR gap|.
9. Diversification / ENB (P4-02) and limits report (P4-03/P4-04 fault tests referenced).
10. gate_report.evaluate_g_research -> outcomes -> combine_tier -> REPORT.md; append the trial-history entries; stop.
```
Source formulas kept: DSR `E[max SR] = sqrt(var_sr)((1-g)Phi^-1(1-1/N) + g Phi^-1(1-1/(Ne)))`; PBO via CSCV with logit lambda; CPCV paths `phi = C(N,k)*k/N` = 9 for N=10, k=2. Where this ticket departs from the source text, the departure is in the OD-16 deviation register, not decided here.

## Tests & acceptance criteria (concrete test file names and assertions)
- `tests/test_gate_report.py` (synthetic outcomes): a hand-built `results` dict with every test passing gives Tier A. One point-estimate failure gives Tier D. A confidence-only miss (DSR 0.90, no point failure) gives Tier C. An ENB miss gives Tier D with reason "H4 ENB miss". Gate 7, one case per decision-table row (P0-08 row 8): (a) passing by at least the margin gives pass; (a) passing by less than the margin with correlation > 0.3 gives `insufficient` (Tier C), with correlation <= 0.3 plus rationale gives pass; (a) failing with correlation > 0.3 gives Tier D, with correlation <= 0.3 plus rationale gives pass. PBO 0.6 with prob_oos_loss 0.3 gives Tier C, not D. A `var_sr` behavioural case: short legacy trials in the family do not raise the length-adjusted var_sr above its null expectation (binding var_sr test required by P0-08). An unusable or low-coverage stress episode gives gate 5 `insufficient`. 12 nearly collinear synthetic grid columns make PBO `uninformative`, not a Tier D failure. The stress reference is computed with the registered bootstrap horizon. PBO with grid N at most 3 is reported "uninformative" and cannot yield "pass". The thresholds are read from a fixture `gates.yaml`, never hard-coded: the test changes the fixture value and sees the verdict change.
- `tests/integrity/test_gates_frozen.py` (P0-08) passes with the real `config/gates.yaml`.
- `tests/test_run_core_v1_evaluation_smoke.py` (new, synthetic panel): `monkeypatch.setenv('FIRM_RESEARCH_LEDGER_ROOT', tmp_path)` is mandatory and the test asserts the host `trials.jsonl` size and mtime are unchanged (or a conftest autouse fixture fails any test touching the default root). Smoke assertions also include: a grid of identical columns gives 9 identical path Sharpes, while a grid whose IS-best flips between halves gives different path Sharpes. The full pipeline runs end to end in under 2 minutes on 3 synthetic instruments and a 3-config grid. It writes REPORT.md with every test row, and `verify_provenance` raises when one trial row is unregistered.
- `tests/integrity/test_report_provenance.py` (new, owned by this ticket; neither P0-04 nor P1-01 defines it; agent drafts, owner commits): every trial_id referenced in `research/reports/**` is in the ledger mirror and verified.
- Acceptance on the real run: REPORT.md states the tier, all eight rows with values, N and var_sr with their sources, the sensitivity results, the data_snapshot_id, and the sentence "all data to 2026-09-30 is in-sample; no post-seal data examined". The prereg enumerates every run with a ledger kind (grid, robustness, cost_stress, stress_suite, benchmark, comparison) and its expected count, and the ledger row count equals that enumerated count (the robustness perturbations, 2x/3x stress, CPCV and BM2 runs are engine runs and each is logged, per P3-09's `LedgerRequiredError`). `gates.yaml` fixes before results that diagnostic kinds count toward N as raw count (OD-09) while only grid trials enter `var_sr`. The trial-history JSON diff shows additions only.

## Definition of done
One run, honestly reported as pass, fail or insufficient. REPORT.md and results.json committed by the owner; `docs/core_v1_trial_history.json` created (agent draft, owner commit) and old entries unchanged afterwards; INDEX.yaml status update drafted by the agent and committed by the owner; a one-paragraph decision note: "Tier A: proceed to P5-01/P6-03" or "Tier C/D or ENB miss: stop; outcome is passive (BM2, or the 92/8 book with its active satellite noted)". If the outcome is Tier C/D, P5-01..P7 are not run for this candidate and the plan records that as a legitimate result.

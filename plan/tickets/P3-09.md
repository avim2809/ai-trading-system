# P3-09 — Signed, multiplier-aware, cost-model vector engine (ledger-logged)

**Phase:** P3 **Status:** ADDED **Depends on:** P3-06, P2-04, P1-01, P0-02, P2-02 **Touches live services:** no **Owner decisions:** none

## Rationale (cite source plan / literature)
The source plan has no engine ticket, yet P3-07, P3-08, P4-02 to P4-04 and P5-04 all need one simulator that handles signed positions, contract multipliers, leverage and a real cost model, and that logs every run. Without it each study would write its own flat-bps loop, which is exactly what the repo's existing `scripts/run_*_evaluation.py` scripts do, and the source's "DO NOT flat bps" and "every backtest logged" rules (P1-01, P2-04) could not be met.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
```
for each bar t (date index):
    pos_t  = target_positions[t - fill_lag_bars]           # decided at close t-1, filled at t  (no look-ahead)
    dq     = pos_t - pos_{t-1}                             # signed trade in units
    pnl_t  = sum_i pos_{t-1,i} * mult_i * (P_{t,i} - P_{t-1,i}) * fx_{t,i}   # P&L on the prior position
    cost_t = sum_i cost_fn(i, t, dq_i, P_{t,i}, adv, vol, mult_i, roll_i, stress).total * fx
    ret_t  = (pnl_t - cost_t - borrow_t) / equity_{t-1}
    equity_t = equity_{t-1} * (1 + ret_t)
```
Clarifications and corrections:
- **Shift rule.** Targets are indexed by the date on which they were decided (close t). The engine itself applies the one-bar fill lag, and the engine's unit test fails if targets at t affect P&L at t. This is the only place the lag is applied (P3-01/02/03 do not shift).
- **Signed and multiplier-aware.** P&L is `pos * mult * dP`. The old `simulate` raised on negative weights, which would silently break a signed system, so this engine has an explicit `allow_short` and no such check.
- **Cost model, not bps.** Every trade calls `cost_fn` (P2-04). Roll costs (two crossings) are charged on `roll_flags` dates. The stress multiplier is passed to `cost_fn`, not applied to a single bps number, so 2x scales commission, fees, half-spread, impact and roll together (G-RESEARCH 4).
- **Equity-based sizing.** Positions are given in units; the engine does not compute sizing (that is P3-06). The optional helper `targets_from_forecasts(...)` wraps P3-06 for a convenience path used by P3-08.
- RECONCILED: **Cash and rf.** The frozen `simulate(cash=True)` credits uninvested cash with `rf[i]` (`rp = w @ r + cash_w * rf[i]`, L144-147), so an engine that pays cash nothing and then subtracts rf on full equity understates excess return by `(1 - gross) * rf`. A long/flat ETF book holds a lot of cash (average combined forecast about 5), so at 50% cash and 2.5% rf that is about 1.25% a year, roughly 0.15 Sharpe at 8% vol, biasing DSR, gate 4 and gate 7 against BM2. The engine therefore takes an optional `rf` series (daily, aligned) and credits `rf_t * (equity_{t-1} - signed market value of positions at t-1)` as cash interest; `excess_returns = returns - rf`, so excess = `sum_i w_i (r_i - rf)`. With `rf=None` the credit is zero and the meta records `rf_used=False`. One Sharpe convention (excess over T-bill, same rf series) is required for the candidate, BM2 and `core_only_100` (P3-08).
- RECONCILED: **Gross-cap diagnostic.** The engine takes unit targets and does no sizing (`max_gross=None`), so it cannot know when the P3-06 cap bound. `targets_from_forecasts` returns the per-day `gross_cap_bound` flags from `gross_cap_scale`; the caller passes them in and the engine stores their mean in `gross_cap_bound_days`.
- **Determinism.** No randomness inside the engine.
- **Ledger.** If `ledger_ctx` is given, the run is recorded through `backtest_logged` (config hash, code commit, data_snapshot_id, returns parquet). With neither `ledger_ctx` nor `exploratory=True` the function raises `LedgerRequiredError`.

## Tests & acceptance criteria (concrete test file names and assertions)
`tests/test_vector_engine.py` (synthetic data and a fake `CostFn` only):
- `test_zero_cost_equals_hand_pnl`: 3 bars, 1 instrument, a known multiplier, a long then flat path, and the net return equals a hand-computed value to 1e-12.
- `test_short_position_pnl_sign`: a short position profits when the price falls.
- `test_no_lookahead_via_target_shift`: shuffling or changing `target_positions` at date t changes returns only from t+1 on.
- `test_multiplier_scaling`: doubling the multiplier with half the units leaves P&L identical.
- `test_costs_use_cost_fn_and_stress`: a fake `CostFn` records `stress`. A run with `stress_multiplier=2.0` yields exactly double the fake's cost totals, and the 3x run triples them.
- `test_roll_cost_charged_on_roll_dates_only`.
- `test_gross_returns_minus_costs_equals_net` (to 1e-12).
- `test_ledger_required`: running without `ledger_ctx` and without `exploratory=True` raises `LedgerRequiredError`. With `exploratory=True` a `mode='exploratory'` row is appended to a tmp-path throwaway ledger (never the host ledger).
- `test_engine_does_not_import_backtrader_or_live`: (a) a static AST check that `vector_engine.py` contains no `import backtrader`/`from backtrader` and no import of `firm.live`/`firm.api`/`firm.runtime`/`scripts`; (b) a subprocess check that importing `firm.backtest.vector_engine` loads none of `firm.live`, `firm.api`, `firm.runtime`. A subprocess `sys.modules` check for `backtrader` is NOT used: the `firm.backtest` package `__init__` loads it regardless.
- `test_rf_credited_on_cash`: a 100%-cash book with rf > 0 has `excess_returns` exactly 0, and a 50%-invested book has excess equal to `0.5*(r - rf)` to 1e-12.
- `test_gross_cap_bound_share`: a fixture where the supplied flags are True on 3 of 10 days reports `gross_cap_bound_days == 0.3`.
- `test_equivalence_with_legacy_simulate_on_long_only` (the TEST, not the module, imports `scripts/run_alt_premia_evaluation.simulate` read-only via `sys.path`): the legacy loop drifts weights, credits cash with `rf[i]`, applies the target decided at close i-1 to day i's return and subtracts `|tgt - w_drifted| @ bps` as a fraction of pre-return equity (L133-164). Mapping: `fill_lag_bars=0` with targets indexed by decision date reproduces that timing, and unit targets are built in the test from the legacy weight path and zero-cost equity. Assertions: (1) zero cost and rf=0 (or `cash=False` in legacy): gross and net returns match to 1e-12; (2) rf given: matches legacy with `cash=True` to 1e-12; (3) nonzero flat-bps cost via the fake `CostFn`: the engine charges a currency cost on post-return equity divided by `equity_{t-1}`, legacy subtracts it as a fraction of pre-return equity, so the two differ by a factor of about `(1+rp)` on each rebalance day (about 1e-6). The test asserts agreement to 1e-5 and also asserts the analytically derived difference to 1e-10. The ticket documents this known accounting difference rather than claiming exact equivalence with the frozen simulator.
- P0-06's isolation test passes with the module present.

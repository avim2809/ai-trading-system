# P3-10 — One-time forward-holdout evaluation of frozen core_v1

**Phase:** P3 **Status:** DEFERRED **Depends on:** P3-08, P0-02 **Touches live services:** no **Owner decisions:** OD-04, OD-05, OD-18

## Rationale (cite source plan / literature)
Source plan P0-02 ("used once per family") and the holdout discipline in A6 (Bailey et al.; Lopez de Prado). Because no historical holdout exists in this repo (all data to 2026-09-30 is burned, design and OD-04), the only clean test of a frozen `core_v1` is forward data from 2026-10-01 onward, evaluated exactly once. OD-18 makes a pass a precondition of the first real-money step (P7-02), labelled as a no-contradiction check and not a proof of edge.

## Repo reconciliation (what exists today, exact paths+line refs, what changes vs source plan and why)
- Reason for deferral: it cannot start before 2027-10-01 (12 months of accrued forward data, OD-16 row "12-month minimum before unseal"), and only if P3-08 returns Tier A.
- Nothing exists today: no unseal script, no token handling, no `research/approvals/`. Post-seal data already sits on this host in several places (design and `docs/HOLDOUT_POLICY.md` from P0-02), so the unseal data is pulled by a script the owner runs, to an off-host or encrypted volume (OD-05). Only the owner holds the token preimage, and `config/research_freeze.yaml` stores its sha256.
- The allocation forward test and the S2 shadow job are exempt as monitors and their outputs are never evidence for new families (design). They are not used here.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
Single evaluation of the frozen `core_v1` config (constants from the P3-11 addendum) on data from 2026-10-01 to the unseal date, against pre-set `gates.yaml` criteria (OD-18): forward net Sharpe not below the 5th percentile of the block-bootstrapped distribution of backtest Sharpes whose path length equals the ACTUAL forward-window length in trading days (recorded at unseal; alternatively `gates.yaml` fixes the forward window to exactly 12 months), because the Sharpe sampling distribution narrows as the window lengthens, and forward max-DD within the charter envelope. The result is recorded as one ledger trial and as an approvals entry. With 12 months of data this is a no-contradiction check, and the report must say so.

## Tests & acceptance criteria (concrete test file names and assertions)
Deferred; when reopened: a synthetic-fixture test that the script refuses a second run, refuses a wrong token hash, and writes exactly one ledger row. Holdout tests use synthetic fixtures only (design).

## Definition of done
Deferred. When run: one ledger trial, one approvals entry, FORWARD_HOLDOUT.md, owner-signed.

4 agent-hours; 90 minutes human review.

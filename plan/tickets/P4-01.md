## Rationale (cite source plan / literature)
Source P4-01: instrument weights are set by handcrafting (Carver, *Systematic Trading*): split risk equally across asset classes, then within each class, then across instruments, with fixed rounded weights chosen without performance input. HRP (Lopez de Prado 2016, "Building Diversified Portfolios that Outperform Out of Sample") is computed only as a diagnostic to compare against the handcrafted weights. The source says switching to HRP would be a new trial.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
- Handcraft: `w[class] = 1/n_classes`; `w[sub] = w[class]/n_subs_in_class`; `w[inst] = w[sub]/n_inst_in_sub`. Instrument weights here are risk-share weights; the sizing step (P3-06) converts them to positions via vol targeting.
- HRP: (1) correlation distance `d = sqrt(0.5*(1-rho))`; (2) hierarchical linkage; (3) quasi-diagonal order; (4) recursive bisection with inverse-variance cluster weights (`w_i = (1/diag(Σ_cluster)) / sum`, cluster variance `w' Σ w`, split `alpha = 1 - V_left/(V_left+V_right)`).
- Bisection is positional (halves the quasi-diagonal order by count, not by dendrogram cluster), matching the legacy code and the original snippet; it equals an inverse-cluster-variance split of the dendrogram only when blocks are equal-size powers of two or contiguous.
- Edge cases: single instrument returns weight 1; NaN in cov, asymmetry, or a diagonal <= 0 raises `ValueError` (no silent fill). Singular or rank-deficient PSD covariances are ACCEPTED (HRP never inverts Sigma; that is its advantage) and must return valid weights.
- Correction vs source: none. Note only that HRP is shown as a diagnostic next to handcrafted weights; it never feeds sizing.

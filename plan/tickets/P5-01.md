## Algorithm notes / pseudocode (keep the source plan formulas exactly where they apply; correct them explicitly if wrong, with reason)
```
transition_allowed(src,dst): only forward edges in the chain, or any -> PROBATION/DECOMMISSIONED/ARCHIVED
forward transition requires: (a) gates.yaml evidence for that edge (e.g. RESEARCH->RESEARCH_PASS needs Tier A report with verified trial_ids), (b) approval file under research/approvals/ (else ApprovalRequiredError; failed evidence -> GateNotMetError), (c) prereg hash match
approval identity check depends on OD-06: if a distinct agent identity is configured (OD-06 option b), verify the approval commit is by the owner identity and reached main via a reviewed PR; if not, the check returns "unverifiable" (never "pass"), and the approval additionally requires a signed commit (GPG/SSH key held only by the owner) or a merged PR approval. GUARDRAIL_REDTEAM.md and the DoD must state that without OD-06(b) approvals are advisory.
EMBARGO -> PAPER: GateNotMetError unless >= 14 calendar days (UTC, from git commit timestamps of the EMBARGO transition, never log lines) have elapsed AND the family's code paths and config hash are unchanged since the EMBARGO transition (compare record.code_commit / config_hash).
LIVE_STEP_1 -> LIVE_STEP_2 and LIVE_STEP_2 -> LIVE_FULL: GateNotMetError unless dwell >= 3 months at the current step (G-LIVE-STEP, from gates.yaml).
PROBATION -> prior_state: allowed only with an approval file (source: human approval "out of PROBATION"); records the new entered_at_utc.
account_type: target_weight_allowed returns False for a PAPER-state family when account_type == "live" (source: allocation "only to PAPER (paper acct) or LIVE").
G-PAPER evaluator covers all five source criteria: 1 (>= 26 events, >= 6 months), 2 (corr/TE), 3 (cost ratio), 4 (position break lasting more than 1 trading day, or an unexplained missed review, fails), 5 (missing kill-switch/combiner fault-drill record fails).
decommission_decision:
  n = int(dd > 1.5*survival_ref) + int(cusum_alarm) + int(fidelity_breach_months >= 2) + int(mechanism_invalid)
  n == 0 -> ok ; n == 1 -> probation (state -> PROBATION, prior_state recorded, target weight UNCHANGED, review opened) ; n >= 2 -> zero_weight (sets zero_weight flag; target weight 0 until an owner approval clears it)
zero_weight persistence: the automatic decision is written atomically (write temp + os.replace) to $FIRM_DATA_DIR/lifecycle_overrides.json {family, zero_weight, triggers, decided_at_utc}. LifecycleGatedSleeve reads it with precedence over registry.yaml; only an approval file clears it. Reason: registry.yaml is owner-committed, and the services run Restart=always with FIRM_AUTO_START_LIVE=1, so an in-memory override would be lost on restart and trading would resume silently (same class as the non-persistent /live/stop and the 8/6 kill-switch persistence bugs).
G-PAPER 3 is "insufficient_data" (not pass) until fills >= 30 and instruments >= 10; paper period is extended, never waived
```
Clock and timestamps come from an injected `now_fn`, never from log lines.

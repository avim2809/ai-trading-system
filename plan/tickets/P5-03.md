## Algorithm notes / pseudocode (keep the source plan formulas exactly where they apply; correct them explicitly if wrong, with reason)
Lower-side CUSUM for decay (we detect a drop from mu0):
```
z_t = (x_t - mu0) / sigma
S_0 = 0
S_t = max(0, S_{t-1} - z_t - k)      # k = (mu0 - mu1) / (2 sigma)
alarm when S_t > h
```
calibrate_h: simulate in-control series (iid normal as baseline, and stationary-bootstrap from a supplied return sample as a robustness variant), find h so that the MEAN run length to first alarm is ARL0 = 5 years x periods/year (1260 daily periods), as in the source. Not the median: run lengths are roughly geometric, median is about 0.7 x mean (simulated 888 vs 1223 at the same h), so the choice would move h far outside any tolerance. Use bisection over h on a calibration seed; return h and record the achieved mean ARL with its standard error. Verification tests use a seed independent of the calibration seed (bisection on fixed draws reproduces the target by construction). Correction to be explicit: with fat tails and autocorrelation the normal-theory ARL is optimistic, so the gate uses the bootstrap-calibrated h if larger. Secondary check: rolling 36-month one-sided t-test (H1: mean excess below mu0) of monthly excess returns, reported with the alarm, never used alone. Documentation note for the docstring: at realistic daily scale (mu0 = SR 0.25 after haircut, mu1 = SR -0.3, ARL0 = 1260) the simulated mean detection delay is about 625 days (median about 484), roughly 2.5 years, so CUSUM is a slow decommission trigger by construction.

## Tests & acceptance criteria (concrete test file names and assertions)
`tests/test_decay.py`:
- `test_in_control_arl_within_tolerance`: h calibrated on seed A; MEAN run length verified on independent seed B within +/-20% of target (source tolerance). Using +/-15% would be an annotated tightening and is optional. Use a small ARL0 (for example 250) to stay fast.
- `test_detection_delay_shift_to_sr_minus_0_3` (source test, restored): mu0 = the charter's haircut SR, mu1 = SR -0.3, converted to per-period units, ARL0 = 1260; compute the mean detection delay by simulation, assert it within +/-20% of a reference simulation (or the Siegmund approximation) and REPORT the value (expected about 2.5 years).
- `test_detects_large_shift_fast`: a large shift (for example mu1 = mu0 - 2 sigma) alarms with median run length < 0.2 x ARL0 (sanity only, not the realistic scenario).
- `test_in_control_alarm_rate`: over many sims, the fraction alarming within n periods is within tolerance of 1 - exp(-n/ARL0). No hand-picked-seed `no alarm in 2000 periods` test: with ARL0 = 1260 a correct CUSUM alarms within 2000 periods in about 83% of runs, so such a test rewards seed-shopping.
- `test_default_k_uses_sigma`: with sigma != 1, default k equals (mu0 - mu1)/(2*sigma).
- `test_t_test_36m_rolling_one_sided`: uses the last 36 months only; p-value sign and magnitude correct for a mean below mu0 versus above mu0.
- `test_cusum_step_equals_cusum_run` (streaming equals batch).
- `test_reset_policy`: after alarm the state is flagged and does not auto-clear (clearing is an owner approval in P5-01).
- `test_unit_guard`: passing an annualised Sharpe where per-period is expected raises (via P1-02 guard).
- `test_deterministic_given_seed`.
- Acceptance: all tests green under `nice -n 10`, runtime < 60 s.

## Algorithm notes / pseudocode (keep the source plan formulas exactly where they apply; correct them explicitly if wrong, with reason)
```
te_ann = std(live_ret - shadow_ret) * sqrt(252) ; pass if te_ann <= 0.25 * tau
corr = corr(live_ret, shadow_ret)                   ; pass if corr >= 0.95
decision_px_i = the ARRIVAL MID at order-submission time, recorded at decision (the reference the cost model assumes). NOT the prior close: that would add overnight drift, which is noise rather than cost, and would make the per-trade median ratio noise-dominated.
shortfall_i = side_i * (fill_i - arrival_mid_i)/arrival_mid_i * 1e4 bps + (commission_i + exchange_fees_i)/notional_i*1e4
modelled_i = CostBreakdown.total (commission + exchange_fees + half_spread + impact)
cost_ratio = realised_cost / modelled_cost (median over trades and aggregate); pass if <= 1.5 each
Fidelity windows (pre-registered in gates.yaml before any paper data; the ticket must not choose them after the fact): corr and TE are evaluated at each month-end over a trailing 63 trading days (or cumulative since paper start, whichever gates.yaml fixes), NOT a calendar month (about 21 points; with true corr about 0.97 a 21-point sample corr falls below 0.95 often enough that two consecutive false breaches are plausible). Zero-exposure days (both series about 0 because the long/flat book is flat) are handled by a fixed rule in gates.yaml (default: excluded from corr, included in TE) and the count of excluded days is reported.
G-PAPER 3 evaluable only if n_fills >= 30 and n_instruments >= 10, else "insufficient_data"
position break: open when discrepancy appears, close when it clears; breach if duration > 1 trading day
missed review: scheduled review date without a recorded decision, or with working orders that blocked it and no logged explanation
```
Monthly breaches (G-PAPER 2 or 3 breach, evaluated on the pre-registered window above) feed P5-01's "fidelity breach in 2 consecutive months" trigger.

## Tests & acceptance criteria (concrete test file names and assertions)
`tests/test_fidelity.py` (synthetic, no network):
- identical live and shadow series -> corr 1.0, TE 0; added noise gives expected TE within tolerance; threshold edges at exactly 0.95 and 25% of tau.
- `test_cost_ratio_exact_zero_slippage`: a zero-slippage fill gives `realised_bps == (commission + exchange_fees)/notional*1e4` and `ratio == realised / modelled.total`, both asserted exactly. (A zero-slippage fill with commission equal to the modelled commission has realised < modelled, so ratio < 1; the earlier "ratio > 1" assertion was wrong.)
- `test_cost_ratio_changes_if_commission_omitted` and `test_cost_ratio_changes_if_fees_omitted`: dropping either term changes the ratio.
- `test_modelled_includes_spread_and_impact`: a model that drops the half-spread or impact terms fails.
- `test_monthly_breach_false_alarm_rate`: a synthetic pair with true corr 0.98, simulated many times, gives two consecutive monthly breaches at no more than a stated false-alarm rate (recorded in the test).
- `test_shadow_replay_post_seal_fixture_without_guard`: shadow replay works on fixture dates after the seal without installing the seal guard; snapshot paths fall under `research/monitoring_sealed/`.
- `test_g_paper_3_insufficient_below_30_fills_or_10_instruments`.
- `test_position_break_duration` across two daily runs; break open > 1 trading day flagged; clears correctly.
- `test_missed_review_stuck_order_counts_unless_explained`.
- `test_only_deterministic_candidates` rejects an IBKR/LLM config.
- `test_no_live_side_effects`: broker and engine write methods monkeypatched to raise.
- Cost-model reconciliation reuse: P2-04's `test_reconcile_10_broker_statement_trades` (skipped stub until real statements exist) is the reference for realised-vs-modelled cost on candidate fills; P5-04 and P6-02 cite it rather than re-implement it.
- `test_daily_state_paths`: the daily job writes only under `data/forward_monitors/` (tmp_path); the owner-run `export` writes only under `research/monitoring_sealed/candidates/`.
- Acceptance: fixture replay reproduces a hand-computed report; isolation test passes.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
1. Day 0: EMBARGO ends (owner records the date). Sleeve weight is set via the lifecycle state (PAPER) under owner approval.
2. Daily: P5-04 computes live-vs-replay return correlation and TE (annualised, divided by tau); CUSUM (P5-03) updates.
3. Weekly: record a review event whether or not trades occurred; record breaks and missed reviews.
4. Monthly: a review document covers G-PAPER for the candidate and I1-I5 for the allocation test side by side, labelled "live comparator, non-evidence" for the Alpaca book.
5. Fault drills once each on :8002, covering `drills_completed` = {data_outage, stale_price_gt_2d, broker_disconnect_in_window, position_break, dd_soft_1_0x, dd_hard_1_5x, decommission_one_trigger (PROBATION), decommission_two_triggers (weight 0)}. Injection is in-process only, via candidate-config-gated test hooks (e.g. stale-quote or disconnect flag) consumed by the P4-04/P5-01 modules on :8002. Each drill record states the injection method and confirms afterwards that the :8000 and :8001 last-cycle timestamps are unaffected. Verified reason: the price cache (`data/cache`, config.py L119) and IB Gateway/nginx/network are shared, so cache edits, egress blocks or stopping providers would hit the control and the forward test.
6. Gate, split to avoid optional stopping: `status='extend'` only when events < 26, months < 6 (whichever later), fills < 30 or instruments < 10. Once those count preconditions are met: corr < 0.95, TE > 0.25 tau, cost_ratio_median > 1.5 or cost_ratio_aggregate > 1.5, max_unreconciled_break_days > 1, unexplained_missed_reviews > 0, or an incomplete `drills_completed` set gives `fail` (incomplete drills: no `pass`; `extend` until done), never `extend`. Each monthly G-PAPER 2/3 breach is also passed to the P5-01 decommission combiner (2 consecutive months is a G-DECOMMISSION trigger). At most one pre-declared re-evaluation date is allowed, recorded in `gates.yaml` before paper starts (source plan has no extension clause beyond the count preconditions).
7. Any parameter change resets the clock and creates a new ledger trial.

## Tests & acceptance criteria (concrete test file names and assertions)
- `tests/test_lifecycle.py` (from P5-01) gains cases using synthetic inputs, thresholds read from `config/gates.yaml`: 25 events returns `extend`; 26 events and 5 months returns `extend`; 26 events in exactly 6 calendar months returns `pass`; 29 fills returns `extend`; 30 fills across 9 instruments returns `extend`; all thresholds met returns `pass`; preconditions met with corr 0.94 returns `fail` (never `extend`); te_ratio 0.26 returns `fail`; cost_ratio_median 1.4 with aggregate 1.6 returns `fail`, and the reverse; a 2-day unreconciled break returns `fail`; a stuck working order without explanation counts as a missed review and returns `fail`; a missing `dd_hard_1_5x` drill means no `pass`.
- Acceptance is by artefacts in `research/monitoring/` and `research/approvals/` reviewed by the owner, not by CI.

## Definition of done
At least 26 review events and 6 months on the candidate account; each G-PAPER 1-5 criterion has a recorded result; all eight drills in `drills_completed` documented; zero unexplained missed reviews; owner approval of pass or extension committed. This is H6.

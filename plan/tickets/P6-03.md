## Rationale (cite source plan / literature)

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
Provisioning order (each step is owner-executed or owner-approved):
1. Verify the preconditions with date -u / git: Tier A report committed, EMBARGO of 14 days elapsed, P5-01 merged.
2. Build the three files in a worktree under `.claude/worktrees/P6-03`; run the full suite and `scripts/live_import_smoke.py` extended with the candidate config (the smoke script may be called with `--config`; if it cannot, run `resolve_live_startup` on the new file in a test).
3. Owner creates the second paper account and installs the credentials file.
4. Owner installs the unit, `nginx -t`, reload (and, only if a new external port was chosen, `ufw allow <port>/tcp`), start. Before the first start, the account-identity check must pass: the broker's account id (via its account endpoint, not .env) differs from the :8001 account's and the book is empty; abort otherwise. Then verify `/api/health` on :8002, `GET /api/live/status` reports broker `alpaca_paper`, and the unit file contains no `FIRM_ALLOW_TRADING` (`trading_armed()` is not exposed by any API router, and paper broker types pass the guard regardless).
5. Confirm :8000 and :8001 are unaffected (status, last cycle timestamps).
The candidate runs with a zero-weight placeholder sleeve until P6-01 lands, so it is inert (zero orders on an empty book). If the placeholder is not used, leave `FIRM_AUTO_START_LIVE` unset for :8002 until P6-01.

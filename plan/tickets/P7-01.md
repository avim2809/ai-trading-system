## Rationale (cite source plan / literature)
Source plan P7-01: choose the instrument set that a given real capital can actually hold (Carver-style minimum-capital logic: integer contracts, margin, minimum position size per instrument). Source A7 puts about $100k as the practical floor for a diversified futures book. The tool uses no performance data, so it can be built before any research verdict.

At $25k-100k with 15-25 ETFs, positions are about $1k-4k, so whole-share rounding of high-priced ETFs is material. The selector therefore applies the min-capital filter with `min_lot=1` share to every `fractional=False` instrument, set from `--broker`/`--domicile`. It must handle both: ETF universe (`config/universe_etf.yaml`, from P2-01) and a futures draft (`config/universe_futures.yaml`).
- Live broker choice (OD-20) affects which instruments are available. Prefer IBKR live because it accepts Israeli residents. Alpaca live availability to an Israeli resident is unconfirmed.
- Tax domicile (OD-12, US-listed vs UCITS) changes the ETF candidate list. It is a placeholder switch in the tool, not a decision.
- P1-03 provides `firm.validation.diversification` (ENB, participation ratio). The selector uses it only for a structural diversification score from correlations of the P2-01 universe, never from strategy returns.
- This script is a scripts/ tool, not a `run_*.py` harness, and it writes no ledger rows. Data design (chosen, resolving the earlier ambiguity): the tool consumes ONE frozen input file (`--inputs`, JSON) holding per-instrument price, `vol_pct`, `fx` (to USD) and the return-correlation matrix. That file is built by a separate step through `firm.research.data_access` with as-of <= 2026-09-30 (the seal date) and carries a `data_snapshot_id` taken from a P2-02 manifest. The selector itself reads no prices; it rejects an input file whose as-of is after the seal date. Correlations are instrument-return correlations only, never strategy returns, so the ENB step is performance-blind.

## Algorithm notes / pseudocode (keep the source plan's formulas exactly where they apply; correct them explicitly if wrong, with reason)
- Path bands, from OD-01, as half-open intervals: [0, 25k) passive only; [25k, 100k) etf (15-25 ETFs, long/flat, no carry); [100k, 250k) micro_hybrid; [250k, inf) futures.
- Min-capital filter, source formula verbatim: `min capital ~= 4 x multiplier x price x FX x sigma% / tau`. For a set of retained instruments with weights w_i and IDM, instrument i is kept iff `capital >= 4 x multiplier_i x price_i x fx_i x vol_pct_i / (IDM x w_i x tau)`. Annotation: the source omits `IDM x w_i` because it states the single-instrument case (IDM = w = 1), to which this reduces exactly. The "4" is the source's four-contracts rule (Carver) and is the default `min_contracts`. This is 4x stricter than an at-least-one-lot rule and is deliberately retained: at 1 contract, forecasts of 5 and 15 round to 0/1/2 contracts (~50% position error) and the P3-06 buffer does nothing. For `fractional=False` ETFs the same formula applies with multiplier = 1 and `min_contracts` replaced by `min_lot` = 1 share.
- Selection (greedy ENB-maximising add, performance-blind): start with the empty set. At each step, for every candidate not yet chosen, form the enlarged set, recompute equal-risk weights w and IDM from its correlation matrix (IDM capped at 2.5 per P3-06), then test (a) the min-capital filter for ALL members of the enlarged set under the recomputed IDM and weights, and (b) the margin cap `sum(margin)/capital <= max_margin_frac`. Among passing candidates add the one that maximises `effective_number_of_bets` (P1-03) of the enlarged set's correlation matrix; break ties by symbol. Stop when no candidate passes. Everything unselected is excluded with reason `min_capital`, `margin_cap` or `no_enb_gain`. Because IDM and weights are recomputed on the retained set, re-running selection on its own output must return the same set (fixed point).
- Futures margin: the sketch's 15-25% estimate (one micro per market, 19 markets, $100k; sketch L229-234) sits at or below the 0.25 default cap, so the cap binds only at the upper end of that range or once IBKR's cushion above SPAN minimums (and the verified margins) push the total above 25%. Granularity (one-lot rounding), not margin, is the binding constraint at $100k (sketch L236-245).
- Output flags `margin_verified=False` instruments with a WARNING line in the report. On the ETF path, emit a WARNING when fewer than 15 instruments survive.
- Output is deterministic and has no randomness.

## Tests & acceptance criteria (concrete test file names and assertions)
`tests/test_select_instruments_for_capital.py`:
- Capital 10_000 returns path "passive" and an empty instrument list.
- Boundaries: 24_999.99 -> passive, 25_000 -> etf, 99_999.99 -> etf, 100_000 -> micro_hybrid, 249_999.99 -> micro_hybrid, 250_000 -> futures.
- Formula: a 1-instrument fixture (IDM = w = 1) matches the source formula `4 x multiplier x price x fx x vol_pct / tau` to 1e-9, hand-computed; capital just below it excludes, just above keeps.
- 4-lot rule: an instrument that would pass at 1 lot but fails at 4 lots is excluded with reason `min_capital`.
- FX: an EUR-denominated fixture instrument with fx=1.1 has a min capital 1.1x that of an otherwise identical fx=1.0 instrument.
- Greedy order: on a fixed 6-instrument correlation fixture, the selected order equals a hand-computed greedy ENB order (ties by symbol), and the retained set's ENB is >= any single-swap alternative.
- Fixed point: re-running selection on the retained set returns the same set (IDM and weights consistent).
- Capital 50_000 with the full ETF fixture returns path "etf", only ETFs, and `15 <= len(instruments) <= 25`; fewer than 15 emits a WARNING (separate fixture).
- Whole-share: a UCITS whole-share fixture at 25_000 excludes a high-priced ETF that the fractional US-listed variant keeps.
- Margin cap: build a fixture whose summed margin exceeds 25% of capital (for example $30k at $100k). Assert retained `margin_to_capital <= 0.25`; adding back the first excluded margin_cap instrument would push it above 0.25 (maximality); and the excluded set equals a hand-computed list, each with reason `margin_cap`.
- Determinism: two runs return identical `Selection`.
- Unverified margins always appear in `warnings`; only MES, MYM, MGC fixtures carry `margin_verified=True`.
- Input guard: an inputs file with as-of after 2026-09-30 is rejected; the `data_snapshot_id` is echoed in the output.
- Static import test: the script may import `firm.research.data_access` (only if it builds inputs) and `firm.validation.diversification`; it must not import `firm.live`, `firm.api`, `firm.data.pit_store`, `firm.runtime`, the ledger, backtest or Sharpe code, or read parquet/returns files directly.
